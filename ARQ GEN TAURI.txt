# ARQ GEN

## ESPECIFICACIÓN TÉCNICA PROGRAMABLE MAESTRA

### Versión 3.0 — Núcleo Generativo Arquitectónico

---

# 0. QUÉ CAMBIA RESPECTO A v1.0 y v2.0

Las versiones anteriores describían **una plataforma CAD/BIM multidisciplinar** donde el arquitecto trabaja. Esta versión describe **un sistema que genera planos arquitectónicos automáticamente, emulando el razonamiento de un arquitecto real, sin IA y sin internet**.

```text
v1.0 / v2.0                     v3.0
─────────────                   ─────
"CAD + presupuesto + CCTV"      "Arquitecto automático"
40 módulos                      Núcleo generativo + extensiones
Centrado en herramientas        Centrado en el razonamiento
Salida: modelo + documentos     Salida: 3 propuestas + plano final
```

**Cambio de centro de gravedad:**

```text
Antes:  UI → usuario dibuja → sistema valida → documenta
Ahora:  UI → usuario describe → sistema genera → arquitecto aprueba → documenta
```

El objetivo real es este:

> Dado un **sitio**, un **programa arquitectónico** (o una descripción de necesidad), una **tipología** y un **ruleset normativo**, el sistema debe producir **propuestas de planta arquitectónica completas, coherentes, acotadas y documentadas**, tal como las produciría un arquitecto humano en las primeras fases de proyecto.

Sin IA. Sin internet. Solo conocimiento experto codificado, reglas, geometría, generación y evaluación.

---

# 1. DEFINICIÓN DEL SISTEMA

ARQ GEN será un sistema profesional de escritorio que **genera automáticamente planos arquitectónicos de edificaciones**, emulando el proceso de diseño de un arquitecto real.

No es un CAD.
No es un editor de planos.
No es un visor BIM.

Es un **generador de diseño arquitectónico asistido por conocimiento experto**.

```text
┌───────────────────────────────────────────────────────────┐
│                     ARQ GEN  v3.0                         │
│                                                           │
│   ENTRADA                    →    SALIDA                  │
│                                                           │
│   Sitio                      →    Planta amueblada        │
│   Programa                   →    Planta acotada          │
│   Tipología                  →    Cuadro de áreas         │
│   Ruleset normativo          →    Memoria descriptiva     │
│   Preferencias               →    3 alternativas          │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

Principio fundamental:

> **El sistema razona como un arquitecto, no dibuja como un delineante.**

# 2. EL PROCESO QUE EMULA

Un arquitecto humano, al proyectar, sigue este proceso:

```text
 1. Comprende el encargo
 2. Analiza el sitio
 3. Consulta las normas aplicables
 4. Recuerda tipologías similares
 5. Define el programa arquitectónico
 6. Organiza zonas (pública / privada / servicio)
 7. Reparte locales dentro de las zonas
 8. Traza circulaciones y accesos
 9. Coloca puertas y ventanas
10. Verifica iluminación, ventilación, evacuación
11. Evalúa la propuesta contra criterios
12. Itera hasta que converge
13. Presenta 2–3 alternativas al cliente
14. Desarrolla la aprobada
15. Documenta: plantas, cotas, cuadros, memoria
```

**ARQ GEN reproduce exactamente este proceso**, pero de forma automática y trazable.

```text
COMPRENSIÓN    →  Motor de Programa
ANÁLISIS       →  Motor de Sitio
NORMATIVA      →  Motor de Reglas
EXPERIENCIA    →  Base de Conocimiento
PROGRAMA       →  Motor de Programa (cierre)
ZONIFICACIÓN   →  Motor de Zonificación
REPARTO        →  Motor Generativo
CIRCULACIÓN    →  Motor de Circulación
APERTURAS      →  Motor de Aperturas
VERIFICACIÓN   →  Motor de Validación
EVALUACIÓN     →  Motor de Evaluación
ITERACIÓN      →  Motor de Refinamiento
PRESENTACIÓN   →  Motor de Alternativas
DESARROLLO     →  Motor de Documentación
```

Cada motor es **una pieza del razonamiento de un arquitecto**.

# 3. LO QUE EL SISTEMA **NO** ES (alcance explícito)

Para no ahogar el proyecto, se define con claridad qué queda **fuera** del núcleo v3.0:

* ❌ No calcula estructura
* ❌ No diseña instalaciones eléctricas, sanitarias, HVAC, gas, pluviales
* ❌ No diseña CCTV, incendio, intrusión, control de acceso, perímetro
* ❌ No computa cantidades ni presupuestos
* ❌ No exporta a IFC/DWG completos
* ❌ No es un CAD editable libremente
* ❌ No es una plataforma multidisciplinar

Todo eso se moverá a **Extensiones Post-MVP** (capítulo 20), y se construirá **sobre** el núcleo, no antes.

> **Regla de oro:** si una pieza no ayuda a *decidir dónde va una pared, un local o una puerta*, no es del núcleo.

---

# 4. ALCANCE DEL MVP (estrecho y profundo)

El MVP no cubre "cualquier edificación". Cubre **una tipología, muy bien resuelta**:

```text
MVP-1: VIVIENDA UNIFAMILIAR
       - 1 o 2 plantas
       - Parcela rectangular o irregular
       - Programa dado por el usuario
       - Ruleset Cuba o genérico
       - Salida: 3 alternativas + plano final + memoria
```

Después del MVP:

```text
MVP-2: VIVIENDA MULTIFAMILIAR (bloques)
MVP-3: ESCUELA PRIMARIA
MVP-4: OFICINA / CORPORATIVO PEQUEÑO
MVP-5: CLÍNICA / CONSULTORIO
MVP-6: COMERCIO / RESTAURANTE
MVP-7: INDUSTRIA LIGERA
```

**Cada tipología nueva se añade como un paquete de conocimiento, no como código nuevo.** Esto es esencial.

# 5. RESTRICCIONES TÉCNICAS

```text
Sistema operativo: Windows (WebView2)
Modo principal: Offline total
Shell: Tauri 2.x
Core generativo: Rust (edición 2021+)
Capa de conocimiento y heurísticas: Python 3.13 (sidecar)
Base de datos: SQLite (WAL)
Persistencia secundaria: JSON + YAML (knowledge base)
Arquitectura: Núcleo generativo + Extensiones
Modelo geométrico: 2D (planta) + 3D ligero (opcional)
Unidades: métricas
Identificación: UUID/GUID persistentes
Cálculo: determinista, incremental, reproducible
Interfaz: WebView2 + WebGL (solo visualización)
Comunicación: IPC Tauri tipado + JSON-RPC al sidecar
IA: ninguna
Internet: no requerido
```

Hardware objetivo:

```text
CPU: Celeron o equivalente
RAM mínima objetivo: 4 GB
Disco: SSD/HDD
```

Consecuencias:

* No cargar el modelo completo en memoria.
* Generación asíncrona con eventos de progreso.
* Caché de candidatos y evaluaciones.
* Determinismo: la misma entrada produce la misma salida (semilla fija).

# 6. PRINCIPIOS DE ARQUITECTURA

```text
1. El razonamiento vive en el CORE (Rust + Python).
2. La UI solo describe, visualiza y aprueba.
3. El conocimiento vive en DATOS, no en código.
4. Toda decisión generada es EXPLICABLE.
5. Toda decisión significativa requiere APROBACIÓN HUMANA.
6. Ningún módulo crea realidad paralela del proyecto.
7. Toda operación es REPRODUCIBLE con la misma semilla.
8. Toda operación es INCREMENTAL: no recalcular lo no afectado.
9. Toda operación es TRAZABLE: cada número tiene origen.
10. Toda operación es TRANSACCIONAL: undo/redo completos.
```

# 8. MODELO SEMÁNTICO DEL PROYECTO

El modelo sigue siendo único. Una pared es una sola pared. Todos los motores consultan el mismo modelo.

## 8.1 Entidades base

```rust
pub struct Entity {
    pub id: Uuid,
    pub r#type: EntityKind,
    pub project_id: Uuid,
    pub created_at: DateTime<Utc>,
    pub updated_at: DateTime<Utc>,

    // Contexto
    Project, Site, Building, Level, Zone,

    Space, Circulation, Opening,
    // Construcción
    Wall, Door, Window, Floor, Ceiling, Roof,
    Stair, Ramp, Column, Beam,
    // Contenido
    Furniture, Fixture, Equipment,
    // Generación
    Candidate, Alternative, Evaluation, Decision,

    Drawing, Schedule, Document,
}
```

# 10. MOTOR DE SITIO

## 10.1 Entrada

* Polígono del sitio (importable o dibujado)
* Orientación (norte)
* Accesos (calle, peatonal)
* Retiros aplicables (del ruleset)
* Restricciones (altura máxima, coeficiente de ocupación, coeficiente de uso)
* Contexto (edificaciones vecinas, si se especifican)

## 10.2 Salida

```rust
pub struct SiteAnalysis {
    pub buildable_polygon: Polygon,

    pub max_footprint: f64,
    pub max_height: f64,
    pub max_floors: u32,
    pub solar_orientation: Orientation,
    pub prevailing_wind: Option<WindDirection>,
    pub accesses: Vec<Access>,
    pub setbacks: Setbacks,
    pub constraints: Vec<SiteConstraint>,
}
```

## 10.3 Funciones

```rust
analyze_site()

detect_access_points()
apply_setbacks()
compute_max_volume()
```

Todo trazable: por qué el polígono edificable tiene esa forma, de qué retiro sale cada borde, etc.

# 11. MOTOR DE PROGRAMA

## 11.1 Dos modos

**Modo A — Programa explícito:**
El usuario entrega la lista de locales con áreas:
```yaml
program:
  - type: bedroom
    count: 3
    area_min: 12
    area_pref: 14
  - type: bathroom
    count: 2
    area_min: 4
  - type: kitchen
    count: 1
    area_min: 8
  ...
```

**Modo B — Programa derivado:**
El usuario entrega una descripción ("vivienda para familia de 4, 120 m², 3 dormitorios") y el sistema **deriva** el programa completo aplicando la tipología y heurísticas.

```text
Input:  "familia de 4, vivienda, 120 m²"
        ↓
[Tipología: single_family_house]
        ↓
[Heurística: family_of_four]
        ↓
Output: 3 dormitorios, 2 baños, sala, comedor,
        cocina, lavandería, vestíbulo, pasillo, terraza
```

## 11.2 Salida

```rust
pub struct ArchitecturalProgram {
    pub typology: String,
    pub total_area_target: f64,
    pub spaces: Vec<SpaceRequirement>,
    pub priorities: Vec<Priority>,
    pub derived_from: Option<String>,
    pub reasoning: Vec<Decision>,
}

pub struct SpaceRequirement {
    pub space_type: String,
    pub count: u32,
    pub area_min: f64,
    pub area_pref: f64,
    pub area_max: f64,
    pub dimension_min: Option<Dimensions>,
    pub properties: SpaceProperties,
```

# 12. BASE DE CONOCIMIENTO

Este es el activo más valioso del sistema. Vive en `knowledge/`. Es **dato**, no código.

## 12.1 Space DNA

```yaml
# knowledge/space_dna/kitchen.yaml
type: kitchen
discipline: architecture
category: service

area:
  min: 6.0
  pref: 9.0
  max: 15.0

dimensions:
  min_width: 1.80
  min_length: 2.40
  min_height: 2.40

properties:
  requires_water: true
  requires_drainage: true
  requires_ventilation: true
  requires_daylight: true
  wet_zone: true
  noise_level: medium
  privacy: low
  occupancy: 3

adjacency:
  required:
    - dining         # debe ser adyacente al comedor
  preferred:
    - laundry
    - service_yard
  avoided:
    - bedroom
    - main_bathroom

circulation:
  is_circulation: false
  accessible_from: [dining, hallway]
  must_not_be_traversed: true

daylight:
  min_window_area_ratio: 0.10   # 10% del área del local
  orientation_preference: east

ventilation:
  natural_required: true
```

```yaml
# knowledge/heuristics/circulation.yaml

    description: "La circulación no debe superar el 15% del área útil"
    severity: warning

  - code: CIRC-002
    description: "El ancho mínimo de pasillo es 0.90 m"
    severity: error
```

Las heurísticas **no son normas legales**. Son **criterios de arquitecto**. Se separan de los rulesets normativos.

# 13. MOTOR DE ZONIFICACIÓN

## 13.1 Zonas arquitectónicas

```text
PÚBLICA      — living, dining, entry, terrace
PRIVADA      — bedrooms, main bathroom, closets
SERVICIO     — kitchen, laundry, storage, service yard
TÉCNICA      — installations room (si aplica)
CIRCULACIÓN  — halls, corridors, stairs
EXTERIOR     — garden, parking, terrace (cubierta)
```

## 13.2 Proceso

```text
1. Agrupar locales en zonas (según tipología + programa)
2. Definir relaciones entre zonas
3. Proponer disposición relativa (zona pública al frente, privada al fondo)
4. Aplicar restricciones del sitio (accesos, orientación, retiros)
5. Generar 1..N alternativas de zoning
```

```rust
}

}
```

# 14. MOTOR GENERATIVO DE LAYOUT

**Este es el motor central del sistema.** Reparte locales dentro de cada zona.

## 14.1 Estrategia en capas

```text
CAPA 1: PARTICIÓN GRUESA
        - Squarified treemap para dividir la zona en áreas
        - Restricciones: áreas mínimas, dimensiones mínimas

CAPA 2: COLOCACIÓN POR RELACIONES
        - Colocar locales "ancla" (entry, hall, kitchen)
        - Colocar locales dependientes por adyacencia

CAPA 3: AJUSTE POR RESTRICCIONES
        - Verificar dimensiones mínimas
        - Verificar accesos
        - Reparar violaciones

CAPA 4: ORIENTACIÓN Y LUZ
        - Orientar locales según preferencia solar
        - Asegurar ventanas en fachadas válidas

CAPA 5: REFINAMIENTO
        - Optimización local (mover, redimensionar)
        - Evaluación
```

## 14.2 Algoritmo base

```rust
pub trait LayoutGenerator {
    fn generate(&self, ctx: &GenerationContext) -> Vec<Candidate>;
}

pub struct GenerationContext {
    pub site: SiteAnalysis,
    pub program: ArchitecturalProgram,
    pub zoning: ZoningScheme,
    pub typology: Typology,
    pub ruleset: Ruleset,
    pub heuristics: Heuristics,
    pub seed: u64,
    pub max_candidates: usize,
}
```

## 14.3 Métodos soportados (sin IA)

* **Squarified treemap** — reparto rectangular rápido y estable.
* **Slice-and-dice** — partición recursiva con orientaciones controladas.
* **Constraint Satisfaction (CSP)** — backtracking con poda.
* **Graph-based placement** — coloca por adyacencia del grafo funcional.
* **Growing / packing** — locales crecen desde anclas.
* **Simulated annealing** — refinamiento opcional (determinista con semilla).
* **Generative grammar** — reglas de reescritura por tipología.

Todos deterministas dado el mismo `seed`.

## 14.4 Salida

```rust
pub struct LayoutResult {
    pub candidate_id: Uuid,
    pub space_polygons: HashMap<Uuid, Polygon>,
    pub walls: Vec<Wall>,
    pub circulation_graph: Graph,
    pub rationale: Vec<Decision>,
}
```

# 18. MOTOR DE EVALUACIÓN

Puntúa cada candidato en múltiples dimensiones. **No hay score único mágico.**

## 18.1 Criterios

```rust
pub struct EvaluationScore {
    pub area_compliance: f64,        // cumplimiento de áreas mínimas/preferidas
    pub adjacency_compliance: f64,   // relaciones funcionales correctas
    pub circulation_ratio: f64,      // % de área circulable vs útil
    pub daylight_score: f64,         // iluminación natural
    pub ventilation_score: f64,      // ventilación cruzada
    pub privacy_score: f64,          // privacidad de zonas
    pub compactness: f64,            // compacidad de la envolvente
    pub structure_economy: f64,      // economía de muros portantes
    pub service_concentration: f64,  // concentración de instalaciones
    pub rule_violations: u32,
    pub heuristic_violations: u32,
}
```

## 18.2 Comparación

```rust
pub fn compare(a: &EvaluationScore, b: &EvaluationScore) -> Comparison {
    // devuelve dominancia parcial, no un número único
}
```

El usuario ve **el vector completo**, no un solo número. Esto permite decisiones informadas: "A es más económica, B tiene mejor iluminación".

# 21. CONTROL DEL ARQUITECTO

Principio central, invariante:

> **ARQ GEN propone; el arquitecto decide.**

Toda decisión significativa pasa por:

```text
DETECT    → el sistema detecta una oportunidad o problema
EXPLAIN   → explica qué detectó y por qué
PROPOSE   → propone una o más soluciones
APPROVE   → el arquitecto aprueba (o rechaza, o pide cambios)
APPLY     → el sistema aplica
VALIDATE  → el sistema revalida el resultado
```

Nada se modifica silenciosamente. Nada se decide sin registro. Nada se ejecuta sin aprobación.

# 24. TRAZABILIDAD

Para cada elemento del plano debe ser posible preguntar:


Cada respuesta viene del registro de `Decision`.

# 0. PROPÓSITO

Este documento define **el motor que decide dónde va cada local** dentro del polígono edificable. Es la pieza que determina si ARQ GEN emula a un arquitecto o si solo reparte cajas.

Su misión:

# 4. EL ALGORITMO EN 6 CAPAS

El motor no genera layouts de una sola vez. Los construye en capas sucesivas, de lo general a lo específico.

```text
┌────────────────────────────────────────────────────────────┐
│  CAPA 1 — ZONIFICACIÓN GEOMÉTRICA                          │
│           Divide el polígono en zonas arquitectónicas      │
│                                                            │
│  CAPA 2 — COLOCACIÓN DE ANCLAS                             │
│           Coloca locales "semilla" (entry, hall, kitchen)  │
│                                                            │
│  CAPA 3 — PROPAGACIÓN POR GRAFO                            │
│           Coloca locales dependientes por adyacencia       │
│                                                            │
│  CAPA 4 — RELLENO Y AJUSTE                                 │
│           Coloca locales restantes en huecos disponibles   │
│                                                            │
│  CAPA 5 — CIRCULACIÓN Y APERTURAS                          │
│           Traza pasillos, puertas y ventanas               │
│                                                            │
│  CAPA 6 — REPARACIÓN Y VALIDACIÓN                          │
│           Repara violaciones, valida coherencia            │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

Cada capa produce un `PartialLayout` que la siguiente capa consume.

# 5. CAPA 1 — ZONIFICACIÓN GEOMÉTRICA

## 5.1 Objetivo

Dividir el polígono edificable en **subpolígonos** correspondientes a zonas arquitectónicas, respetando restricciones del sitio.

## 5.2 Entrada

```rust
pub struct ZoningInput {
    pub buildable: EditablePolygon,
    pub zones: Vec<ZoneRequirement>,
    pub site: SiteAnalysis,
    pub typology: Typology,
}

pub struct ZoneRequirement {
    pub kind: ZoneKind,
    pub target_area: f64,
    pub priority: f64,
    pub preferred_position: Option<ZonePosition>,
}

pub enum ZonePosition {
    NearStreetAccess,      // frente
    FarFromStreetAccess,   // fondo
    NearServiceAccess,     // lateral de servicio
    PerimeterFacing,       // da al perímetro
    Center,                // núcleo
}
```

## 5.3 Estrategia

```text
1. Determinar orientaciones preferidas por zona según tipología
   (ej: pública al frente, privada al fondo, servicio al lateral)

2. Convertir preferencias en un eje de corte principal
   (paralelo o perpendicular al frente)

3. Aplicar "slicing" recursivo:
   - Primer corte: separa pública + circulación de privada + servicio
   - Segundo corte: separa servicio de privada
   - Tercer corte (si aplica): separa circulación

4. Verificar que cada zona tiene área suficiente (± 10% del target)

5. Si alguna zona queda fuera de rango, retroceder y ajustar cortes
```

## 5.4 Algoritmo: Slicing con posición preferida

```rust
fn zone_slicing(
    polygon: &EditablePolygon,
    zones: &[ZoneRequirement],
    site: &SiteAnalysis,
) -> Vec<ZonePlacement> {
    // 1. Ordenar zonas por prioridad de posición
    let ordered = order_by_position(zones, site);

    // 2. Determinar eje de corte dominante
    let axis = dominant_axis(polygon, site.street_direction);

    // 3. Cortar recursivamente
    let mut placements = Vec::new();
    let mut remaining = polygon.clone();
    let mut remaining_zones = ordered.clone();

    while !remaining_zones.is_empty() {
        let zone = remaining_zones.remove(0);
        if remaining_zones.is_empty() {
            placements.push(ZonePlacement {
                kind: zone.kind,
                polygon: remaining.clone(),
                ..
            });
            break;
        }

        let ratio = zone.target_area / total_area(&remaining);
        let (front, back) = slice_polygon(&remaining, axis, ratio);

        placements.push(ZonePlacement {
            kind: zone.kind,
            polygon: front,
            ..
        });
        remaining = back;
    }

    placements
}
```

## 5.5 Generación de variantes

Para cada zona se generan **3–5 esquemas alternativos** variando:

* el eje de corte (paralelo o perpendicular),
* el orden de corte,
* la proporción exacta.

Esto produce **N esquemas de zonificación** que alimentan la capa siguiente.

# 6. CAPA 2 — COLOCACIÓN DE ANCLAS

## 6.1 Objetivo

Colocar los locales **semilla** de cada zona. Un ancla es un local que:

* tiene posición obligatoria (entry, hall),
* o es centro funcional de su zona (kitchen en servicio, living en pública),
* o determina la circulación (stair, corridor).

## 6.2 Identificación de anclas

Según tipología y programa:

```rust
fn identify_anchors(program: &ArchitecturalProgram, typology: &Typology) -> Vec<Uuid> {
    let mut anchors = Vec::new();

    // 1. Acceso principal siempre es ancla
    anchors.push(program.entry_hall());

    // 2. Locales marcados en la tipología como "anchor"
    for space in &program.spaces {
        if typology.is_anchor(&space.space_type) {
            anchors.push(space.id);
        }
    }

    // 3. Locales con relación "MustAccessFrom" múltiple
    anchors.extend(program.high_connectivity_spaces());

    anchors
}
```

## 6.3 Reglas de colocación de anclas

| Ancla | Posición preferida |
| :--- | :--- |
| Entry hall | Adyacente al acceso principal del sitio |
| Living room | Orientación solar preferida, cerca de entry |
| Kitchen | Adyacente a comedor, con fachada exterior (ventilación) |
| Stair | Centro de gravedad de la circulación |
| Service yard | Adyacente al acceso de servicio |

## 6.4 Algoritmo

```rust
fn place_anchor(
    anchor: &SpaceRequirement,
    zone: &ZonePlacement,
    site: &SiteAnalysis,
    dna: &SpaceDNA,
) -> SpacePlacement {
    // 1. Determinar borde objetivo del polígono de zona
    let target_edge = select_target_edge(zone, anchor, site);

    // 2. Calcular rectángulo semilla
    let dims = preferred_dimensions(anchor, dna);
    let seed_rect = build_seed_rect(target_edge, dims, zone);

    // 3. Verificar que cabe; si no, reducir proporcionalmente
    let fitted = fit_within(seed_rect, zone.polygon, dna.area_min);

    // 4. Restar del polígono de zona
    SpacePlacement {
        space_id: anchor.id,
        polygon: fitted,
        placed_at_step: 0,
        rationale: PlacementRationale {
            method: PlacementMethod::Seed,
            anchor: None,
            constraint_source: vec!["typology.anchor".into()],
        },
        ..
    }
}
```

# 7. CAPA 3 — PROPAGACIÓN POR GRAFO

## 7.1 Objetivo

Colocar locales que tienen **relación obligatoria** con anclas ya colocadas.

## 7.2 Orden de propagación

Los locales se ordenan por:

```text
prioridad = (n_relaciones_obligatorias × 3.0)
          + (n_relaciones_preferidas × 1.0)
          + (peso_zonificación)
          - (dificultad_de_colocación)
```

Se colocan **primero los más restringidos** (mayor prioridad). Esto reduce backtracking.

## 7.3 Algoritmo por local

```rust
fn place_by_adjacency(
    space: &SpaceRequirement,
    placed: &HashMap<Uuid, SpacePlacement>,
    graph: &FunctionalGraph,
    zone: &ZonePlacement,
) -> Option<SpacePlacement> {
    // 1. Obtener vecinos ya colocados
    let neighbors = graph.required_neighbors_of(space.id)
        .filter(|n| placed.contains_key(n));

    if neighbors.is_empty() {
        return None;  // no hay de dónde colgarse
    }

    // 2. Para cada vecino, calcular franjas candidatas
    let mut candidates = Vec::new();
    for neighbor_id in neighbors {
        let neighbor = &placed[&neighbor_id];
        let strips = adjacent_strips(&neighbor.polygon, &zone.polygon);

        for strip in strips {
            if strip.area >= space.area_min {
                candidates.push((neighbor_id, strip));
            }
        }
    }

    // 3. Ordenar por calidad de la franja
    candidates.sort_by(|a, b| {
        let qa = strip_quality(&a.1, space);
        let qb = strip_quality(&b.1, space);
        qb.partial_cmp(&qa).unwrap()
    });

    // 4. Tomar la mejor
    candidates.into_iter().next().map(|(neighbor_id, strip)| {
        let placement = build_space_on_strip(space, strip);
        SpacePlacement {
            space_id: space.id,
            polygon: placement,
            rationale: PlacementRationale {
                method: PlacementMethod::Adjacent,
                anchor: Some(neighbor_id),
                constraint_source: vec![format!("adjacent_to:{}", neighbor_id)],
            },
            ..
        }
    })
}
```

## 7.4 Función `adjacent_strips`

Dado un polígono ya colocado y el polígono de zona, devuelve las **franjas candidatas** donde puede crecer el nuevo local:

```text
┌──────────────────────────────────┐
│         ZONA DISPONIBLE          │
│                                  │
│   ┌────────────┐                 │
│   │  NEIGHBOR  │◄── franja este  │
│   └────────────┘                 │
│        ▲                         │
│        │                         │
│        franja sur                │
│                                  │
└──────────────────────────────────┘
```

Se generan franjas por cada lado del vecino que dé a espacio disponible, con **ancho mínimo** compatible con las dimensiones del nuevo local.

## 7.5 Función `strip_quality`

Evalúa una franja candidata:

```rust
fn strip_quality(strip: &Polygon, space: &SpaceRequirement) -> f64 {
    let area_score = 1.0 - (strip.area - space.area_pref).abs() / space.area_pref;
    let aspect_score = aspect_ratio_quality(strip, space);
    let daylight_score = exterior_edge_ratio(strip);
    let shape_score = rectangularity(strip);

    area_score * 0.35
        + aspect_score * 0.25
        + daylight_score * 0.20
        + shape_score * 0.20
}
```

# 8. CAPA 4 — RELLENO Y AJUSTE

## 8.1 Objetivo

Colocar locales que **no tienen relación obligatoria** con ningún colocado, o que quedaron pendientes tras la propagación.

## 8.2 Estrategia

```text
1. Identificar huecos disponibles en el polígono de zona
2. Para cada hueco, evaluar qué local encaja mejor
3. Colocar por mejor encaje (greedy)
4. Si no cabe ninguno, marcar para reparación
```

## 8.3 Algoritmo

```rust
fn fill_remaining(
    remaining: &[SpaceRequirement],
    zone: &ZonePlacement,
    placed: &HashMap<Uuid, SpacePlacement>,
) -> FillResult {
    let holes = detect_holes(&zone.polygon, placed);
    let mut assignments = Vec::new();

    for hole in holes {
        let best = remaining.iter()
            .filter(|s| s.area_min <= hole.area)
            .max_by(|a, b| {
                let qa = hole_fit_quality(&hole, a);
                let qb = hole_fit_quality(&hole, b);
                qa.partial_cmp(&qb).unwrap()
            });

        if let Some(space) = best {
            assignments.push((space.id, hole));
        }
    }

    FillResult { assignments }
}
```

## 8.4 Función `hole_fit_quality`

```rust
fn hole_fit_quality(hole: &Hole, space: &SpaceRequirement) -> f64 {
    let area_ratio = space.area_pref / hole.area;
    let area_score = if area_ratio > 1.0 {
        1.0 / area_ratio           // penaliza que no quepa
    } else {
        area_ratio                 // premia que se ajuste
    };

    let aspect_score = aspect_compatibility(hole, space);
    let adjacency_score = adjacency_bonus(hole, space);

    area_score * 0.50
        + aspect_score * 0.30
        + adjacency_score * 0.20
}
```

# 9. CAPA 5 — CIRCULACIÓN Y APERTURAS

## 9.1 Objetivo

Convertir el layout en un plano **circulable**:

* trazar pasillos que conecten todos los locales,
* colocar puertas de acceso a cada local,
* colocar ventanas en fachadas y patios.

## 9.2 Grafo de circulación

```rust

    Ramp,
    Opening,
```

## 9.3 Algoritmo de trazado

```text
1. Construir grafo de accesibilidad:
   - cada local es un nodo
   - dos locales son conectables si comparten pared
   - locales con "MustAccessFrom" crean aristas dirigidas

2. Identificar árbol de circulación mínima:
   - Prim/Kruskal con pesos = 1 / preferencia_de_conexión
   - raíz = entry hall

3. Para cada arista, trazar apertura:
   - si dos locales comparten pared → colocar puerta
   - si hay que atravesar un local intermedio → crear corredor

4. Verificar que todo local habitable es alcanzable
   - si no, marcar para reparación
```

## 9.4 Colocación de puertas

```rust
fn place_door(
    from: &SpacePlacement,
    to: &SpacePlacement,
    dna_from: &SpaceDNA,
    dna_to: &SpaceDNA,
) -> Option<Door> {
    // 1. Encontrar paredes compartidas
    let shared = shared_walls(&from.polygon, &to.polygon);
    if shared.is_empty() {
        return None;
    }

    // 2. Elegir la mejor pared compartida
    let best_wall = shared.iter().max_by_key(|w| wall_quality(w, from, to))?;

    // 3. Determinar posición sobre la pared
    let position = door_position_on_wall(best_wall, dna_from, dna_to);

    // 4. Ancho según uso
    let width = door_width_for(from.space_type, to.space_type, dna_from, dna_to);

    // 5. Swing según convención
    let swing = door_swing_direction(from, to);

    Some(Door {
        wall_id: best_wall.id,
        position,
        width,
        swing,
        ..
    })
}
```

## 9.5 Colocación de ventanas

```rust
fn place_windows(
    space: &SpacePlacement,
    dna: &SpaceDNA,
    ruleset: &Ruleset,
) -> Vec<Window> {
    let mut windows = Vec::new();

    // 1. Calcular área mínima requerida
    let required = space.area * dna.daylight.min_window_area_ratio;

    // 2. Iterar sobre bordes exteriores
    let mut remaining = required;
    for edge in &space.exterior_edges {
        if remaining <= 0.0 {
            break;
        }

        // 3. Verificar que el borde da a fachada válida
        if !is_valid_facade(edge, ruleset) {
            continue;
        }

        // 4. Colocar ventana centrada en el borde
        let window = build_window(edge, dna, remaining);

        remaining -= window.area();
        windows.push(window);
    }

    windows
}
```

# 10. CAPA 6 — REPARACIÓN Y VALIDACIÓN

## 10.1 Objetivo

Detectar y **reparar** violaciones de restricciones. Sin reparación, la mayoría de candidatos serían inservibles.

## 10.2 Tipos de violación reparables

| Violación | Estrategia de reparación |
| :--- | :--- |
| Local sin acceso a circulación | Trazar corredor secundario |
| Área fuera de rango | Ajustar vecino menos restringido |
| Local sin ventana | Redirigir borde a fachada |
| Proporción excesiva | Dividir local o subdividir |
| Relación prohibida | Intercambiar dos locales |
| Circulación > 15% | Compactar pasillo |
| Superposición de paredes | Reajustar cotas |
| Local huérfano | Reconectar al grafo |

## 10.3 Política de reparación

```rust
pub struct RepairPolicy {
    pub max_iterations: u32,          // default 20
    pub accept_partial: bool,         // default true
    pub strategies: Vec<RepairStrategy>,
}

pub enum RepairStrategy {
    AdjustArea(Uuid, f64),            // ajustar área a ±delta
    SwapSpaces(Uuid, Uuid),           // intercambiar dos locales
    InsertCorridor(Vec<Uuid>),        // insertar corredor
    SplitSpace(Uuid),                 // dividir un local
    MergeSpaces(Uuid, Uuid),          // fusionar dos locales
    RerouteDoor(Uuid),                // mover una puerta
}
```

## 10.4 Algoritmo

```rust
fn repair(candidate: &mut Candidate, policy: &RepairPolicy) -> RepairResult {
    for iteration in 0..policy.max_iterations {
        let violations = validate(candidate);
        if violations.is_empty() {
            return RepairResult::Success;
        }

        // Ordenar por severidad
        let mut sorted = violations.clone();
        sorted.sort_by_key(|v| std::cmp::Reverse(v.severity));

        // Aplicar estrategia más simple para la más severa
        let v = &sorted[0];
        let strategy = select_strategy(v, policy);
        apply_strategy(candidate, strategy);

        // Registrar decisión
        candidate.lineage.push(Decision {
            entity_id: candidate.id,
            rule_or_heuristic: format!("repair:{:?}", strategy),
            explanation: format!("Reparando violación: {:?}", v.kind),
            ..
        });
    }

    RepairResult::Partial
}
```

# 11. BUCLE GENERATIVO COMPLETO

```rust
pub fn generate_layouts(input: LayoutInput) -> LayoutOutput {
    let mut rng = SmallRng::seed_from_u64(input.seed);
    let mut candidates = Vec::new();
    let mut all_decisions = Vec::new();

    // FASE 1: generar zonificaciones
    let zonings = generate_zonings(&input, &mut rng);

    // FASE 2: para cada zonificación, generar N layouts
    let per_zoning = input.max_candidates / zonings.len();

    for zoning in zonings {
        for i in 0..per_zoning {
            let mut partial = PartialLayout::new(zoning.clone());

            // CAPA 2: anclas
            partial = place_anchors(partial, &input, &mut rng);

            // CAPA 3: propagación
            partial = propagate_by_graph(partial, &input, &mut rng);

            // CAPA 4: relleno
            partial = fill_remaining(partial, &input, &mut rng);

            // CAPA 5: circulación
            partial = route_circulation(partial, &input);

            // CAPA 6: aperturas
            partial = place_openings(partial, &input);

            // Convertir a candidato
            let mut candidate = partial.into_candidate();

            // Reparar
            let repair_result = repair(&mut candidate, &input.repair_policy());
            candidate.status = match repair_result {
                RepairResult::Success => CandidateStatus::Repaired,
                RepairResult::Partial => CandidateStatus::Repaired,
            };

            all_decisions.extend(candidate.lineage.clone());
            candidates.push(candidate);
        }
    }

    // FASE 3: evaluación
    for c in &mut candidates {
        c.score = Some(evaluate(c, &input));
        c.status = CandidateStatus::Evaluated;
    }

    // FASE 4: refinamiento
    if input.mode != GenerationMode::Fast {
        let rounds = match input.mode {
            GenerationMode::Balanced => 2,
            GenerationMode::Deep => 5,
            _ => 0,
        };
        candidates = refine(candidates, rounds, &input, &mut rng);
    }

    // FASE 5: selección
    let best_three = select_diverse_best(&candidates, 3);

    LayoutOutput {
        candidates,
        best_three,
        generation_stats: compute_stats(&candidates),
        decisions: all_decisions,
        total_elapsed_ms: 0, // medido externamente
    }
}
```

# 12. MOTOR DE REFINAMIENTO

## 12.1 Estrategia

```text
1. Ordenar candidatos por dominancia parcial
   (no por score único)
2. Tomar top K (K = 30% del total)
3. Para cada uno, generar M mutantes:
   - mover un local a otra posición
   - intercambiar dos locales
   - redimensionar un local
   - recolocar puertas
   - ajustar corredor
4. Evaluar mutantes
5. Reemplazar si mejoran en dominancia
6. Repetir hasta agotar rondas
```

## 12.2 Política de mutación

```rust
pub struct MutationPolicy {
    pub mutations_per_candidate: usize,   // default 5
    pub mutation_weights: HashMap<MutationKind, f64>,
}

pub enum MutationKind {
    SwapAdjacentSpaces,
    ShiftSpaceWithinZone,
    AdjustSpaceArea(f64),
    RerouteCorridor,
    MoveDoor,
    AddWindow,
    RemoveSpace,
}

fn mutate(
    parent: &Candidate,
    policy: &MutationPolicy,
    input: &LayoutInput,
    rng: &mut SmallRng,
) -> Vec<Candidate> {
    let mut mutants = Vec::new();
    for _ in 0..policy.mutations_per_candidate {
        let kind = weighted_sample(&policy.mutation_weights, rng);
        let mutant = apply_mutation(parent, kind, input, rng);

        // Registrar linaje
        mutant.lineage.push(Decision {
            entity_id: mutant.id,
            rule_or_heuristic: format!("mutation:{:?}", kind),
            explanation: format!("Mutación de {:?}", parent.id),
            ..
        });

        mutants.push(mutant);
    }
    mutants
}
```

## 12.3 Selección por dominancia parcial

```rust
fn dominates(a: &EvaluationScore, b: &EvaluationScore) -> bool {
    let criteria = [
        a.area_compliance, b.area_compliance,
        a.adjacency_compliance, b.adjacency_compliance,
        a.circulation_ratio, b.circulation_ratio,
        a.daylight_score, b.daylight_score,
        a.ventilation_score, b.ventilation_score,
        a.privacy_score, b.privacy_score,
        a.compactness, b.compactness,
        a.structure_economy, b.structure_economy,
    ];

    let mut all_ge = true;
    let mut any_gt = false;

    for i in (0..criteria.len()).step_by(2) {
        if criteria[i] < criteria[i+1] { all_ge = false; }
        if criteria[i] > criteria[i+1] { any_gt = true; }
    }

    all_ge && any_gt
}
```

**No hay un score único.** Se compara por **dominancia de Pareto**, que es la forma arquitectónicamente honesta.

# 13. SELECCIÓN DE LAS 3 ALTERNATIVAS

## 13.1 Objetivo

De todos los candidatos, elegir **3 que sean buenos y distintos entre sí**.

## 13.2 Estrategia

```rust
fn select_diverse_best(candidates: &[Candidate], k: usize) -> Vec<Uuid> {
    // 1. Filtrar a candidatos válidos
    let valid: Vec<_> = candidates.iter()
        .filter(|c| c.score.is_some())
        .collect();

    // 2. Ordenar por dominancia
    let frontier = pareto_frontier(&valid);

    // 3. Seleccionar k con máxima diversidad
    let mut selected = Vec::new();
    selected.push(frontier[0].id);

    while selected.len() < k {
        let next = frontier.iter()
            .filter(|c| !selected.contains(&c.id))
            .max_by_key(|c| min_distance_to_selected(c, &selected))
            .unwrap();
        selected.push(next.id);
    }

    selected
}
```

## 13.3 Distancia entre candidatos

```rust
fn layout_distance(a: &Candidate, b: &Candidate) -> f64 {
    // Diferencia en posición de espacios clave
    let mut d = 0.0;

    for (id, space_a) in &a.spaces {
        if let Some(space_b) = b.spaces.get(id) {
            d += centroid_distance(&space_a.polygon, &space_b.polygon);
            d += (space_a.area - space_b.area).abs();
        }
    }

    d + topological_distance(&a.circulation, &b.circulation)
}
```

Esto garantiza que las 3 alternativas sean **cualitativamente distintas**, no variaciones de la misma.

# 1.4 CATÁLOGO DE CRITERIOS

## 1.4.1 `area_compliance`

**Pregunta:** ¿cada local cumple sus áreas mínimas y preferidas?

```text
Para cada local:
  si area < min:   score_local = 0
  si area > max:   score_local = max(0, 1 - (area - max) / max)
  si min ≤ area ≤ pref: score_local = 0.7 + 0.3 × (area - min) / (pref - min)
  si pref < area ≤ max: score_local = 1.0 - 0.3 × (area - pref) / (max - pref)

score_global = media ponderada por área objetivo
```

Rango: `[0.0, 1.0]`. Dirección: mayor es mejor.

## 1.4.2 `adjacency_compliance`

**Pregunta:** ¿se cumplen las relaciones funcionales obligatorias y preferidas?

```text
score = (Σ peso_relación × cumple_relación) / Σ peso_relación

peso_relación:
  RequiredAdjacent     = 3.0
  MustAccessFrom       = 3.0
  PreferredAdjacent    = 1.0
  VisualConnection     = 0.5
  AcousticSeparation   = 2.0
  ServiceCluster       = 1.5

cumple_relación:
  = 1.0 si se cumple
  = 0.5 si se cumple parcialmente (adyacente indirecto)
  = 0.0 si se viola
```

Rango: `[0.0, 1.0]`.

## 1.4.3 `circulation_ratio_score`

**Pregunta:** ¿la circulación está dentro de rango arquitectónico?

```text
ratio = circulation_area / usable_area

rango ideal: 0.08 – 0.15
  ratio < 0.08  → score = ratio / 0.08 × 0.7
  ratio en rango → score = 1.0
  ratio > 0.15  → score = max(0, 1 - (ratio - 0.15) / 0.15)
```

Rango: `[0.0, 1.0]`.

## 1.4.4 `daylight_score`

**Pregunta:** ¿cada local habitable tiene iluminación natural suficiente?

```text
Para cada local habitable:
  ratio = window_area / space_area
  min_ratio = DNA.daylight.min_window_area_ratio (default 0.10)

  si ratio ≥ min_ratio:     score_local = min(1.0, ratio / min_ratio)  (cap a 1.0)
  si ratio < min_ratio:     score_local = ratio / min_ratio × 0.5

  bonus por orientación favorable:
    + 0.1 si ventana orientada según preferencia solar del DNA

score_global = media de score_local
```

Rango: `[0.0, 1.1]`, truncado a `[0.0, 1.0]`.

## 1.4.5 `ventilation_score`

**Pregunta:** ¿existe ventilación natural efectiva?

```text
Para cada local habitable:
  tiene_ventana_exterior = bool
  tiene_ventana_opuesta = bool (bordes opuestos con ventanas)
  tiene_ventilación_cruzada = tiene_ventana_exterior && tiene_ventana_opuesta

  score_local:
    sin ventana exterior        → 0.0
    una ventana exterior        → 0.5
    ventilación cruzada         → 1.0

  bonus:
    + 0.1 si orientación favorable al viento predominante (si se conoce)

score_global = media
```

## 1.4.6 `privacy_score`

**Pregunta:** ¿los locales privados están protegidos de accesos y vistas indebidas?

```text
Para cada local con DNA.privacy = high:
  penalizaciones:
    - 0.3 si es adyacente directo a local de zona pública
    - 0.3 si es atravesado por circulación
    - 0.2 si comparte puerta con local público
    - 0.2 si su única ventana da a local público

score_local = max(0, 1 - Σ penalizaciones)
score_global = media de score_local para locales con privacy=high
```

## 1.4.7 `compactness_score`

**Pregunta:** ¿la envolvente es compacta (menos muros exteriores por área)?

```text
perimeter = perímetro total de la envolvente
area = área total construida
compactness_ratio = perimeter / (2 × sqrt(π × area))

score:
  ratio ≤ 1.05 → 1.0
  ratio ≤ 1.30 → 1.0 - (ratio - 1.05) / 0.25 × 0.5
  ratio > 1.30 → max(0, 0.5 - (ratio - 1.30) / 0.50 × 0.5)
```

## 1.4.8 `structure_economy_score`

**Pregunta:** ¿el layout permite una estructura económica?

```text
muros_portantes = muros alineados con ejes estructurales
longitud_portante = Σ longitud de muros portantes
longitud_total = Σ longitud de todos los muros

ratio = longitud_portante / longitud_total

score:
  ratio ≥ 0.70 → 1.0
  ratio ≥ 0.50 → 0.5 + (ratio - 0.50) × 2.5
  ratio < 0.50 → ratio × 1.0
```

## 1.4.9 `service_concentration_score`

**Pregunta:** ¿los locales húmedos están concentrados (menos recorrido de tubería)?

```text
locales_humedos = [kitchen, bathrooms, laundry, service_yard]

D = diámetro del círculo mínimo que contiene los centroides de todos

score:
  D ≤ 3.0 m → 1.0
  D ≤ 8.0 m → 1.0 - (D - 3.0) / 5.0 × 0.5
  D > 8.0 m → max(0, 0.5 - (D - 8.0) / 8.0 × 0.5)
```

## 1.4.10 `orientation_score`

**Pregunta:** ¿los locales están orientados según preferencias climáticas?

```text
Para cada local con DNA.orientation_preference:
  si su ventana principal da en la dirección preferida → 1.0
  si da en dirección aceptable → 0.6
  si da en dirección desfavorable → 0.2
  sin ventana → 0.0

score_global = media
```

## 1.4.11 `furniture_fit_score`

**Pregunta:** ¿cabe el mobiliario obligatorio con sus holguras?

```text
Para cada local:
  requeridos = DNA.furniture.required
  caben = Σ (mobiliario que cabe con holgura)
  ratio = caben / len(requeridos)

  penalización por cada solapamiento: -0.2
  penalización por holgura violada: -0.1

score_local = max(0, ratio - penalizaciones)
score_global = media
```

## 1.4.12 `egress_score`

**Pregunta:** ¿se cumplen las condiciones de evacuación?

```text
verificaciones:
  - todo local habitable alcanza la salida en ≤ N pasos del grafo
  - la distancia recorrida al exterior ≤ máxima según ruleset
  - no hay cuellos de botella (pasos con ancho < mínimo)
  - el ancho de circulación ≥ mínimo

score = verificaciones_cumplidas / verificaciones_totales
```

# 1.5 COMPARACIÓN POR DOMINANCIA DE PARETO

```rust
pub fn dominates(a: &EvaluationScore, b: &EvaluationScore) -> bool {
    let pa = a.pareto_vector();
    let pb = b.pareto_vector();

    let mut all_ge = true;
    let mut any_gt = false;

    for (x, y) in pa.iter().zip(pb.iter()) {
        if x < y { all_ge = false; break; }
        if x > y { any_gt = true; }
    }

    all_ge && any_gt
}

impl EvaluationScore {
    pub fn pareto_vector(&self) -> Vec<f64> {
        vec![
            self.area_compliance,
            self.adjacency_compliance,
            self.circulation_ratio_score,
            self.daylight_score,
            self.ventilation_score,
            self.privacy_score,
            self.compactness_score,
            self.structure_economy_score,
            self.service_concentration_score,
            self.orientation_score,
            self.furniture_fit_score,
            self.egress_score,
        ]
    }
}
```

Reglas:
- **Antisimétrica:** si A domina a B, B no domina a A.
- **Transitiva:** si A domina a B y B domina a C, A domina a C.
- Candidatos no dominados forman el **frente de Pareto**.

# 1.6 FRENTE DE PARETO Y SELECCIÓN

```rust
pub fn pareto_frontier(candidates: &[&Candidate]) -> Vec<&Candidate> {
    let mut frontier = Vec::new();

    for c in candidates {
        let dominated = candidates.iter().any(|other| {
            other.id != c.id
                && dominates(&other.score, &c.score)
        });

        if !dominated {
            frontier.push(*c);
        }
    }

    frontier
}
```

La presentación al usuario **siempre** parte del frente de Pareto. Nunca se oculta un candidato bueno en algún criterio por tener un promedio menor.

# 2.6 PASO 1 — GRAFO DE ACCESIBILIDAD

## 2.6.1 Regla base

Dos locales son **conectables** si:

* comparten al menos una pared de longitud ≥ 0.80 m;
* ninguno tiene DNA que prohíba esa conexión mutua;
* la conexión no viola `AcousticSeparation`.

```rust
fn build_accessibility_graph(
    candidate: &Candidate,
    dna: &HashMap<SpaceType, SpaceDNA>,
) -> AccessibilityGraph {
    let mut g = AccessibilityGraph::new();

    for (id_a, a) in &candidate.spaces {
        g.add_node(*id_a);
    }

    for (id_a, a) in &candidate.spaces {
        for (id_b, b) in &candidate.spaces {
            if id_a >= id_b { continue; }

            let shared = shared_walls(&a.polygon, &b.polygon);
            let usable = shared.iter().filter(|w| w.length >= 0.80);

            if usable.count() == 0 { continue; }
            if !can_connect(a.space_type, b.space_type, dna) { continue; }

            g.add_edge(*id_a, *id_b, EdgeInfo {
                shared_walls: usable.collect(),
                kind: classify_edge(a, b, dna),
            });
        }
    }

    g
}
```

## 2.6.2 Clasificación de aristas

```rust
fn classify_edge(a: &SpacePlacement, b: &SpacePlacement, dna: &HashMap<SpaceType, SpaceDNA>) -> EdgeClass {
    let must_from = dna[&a.space_type].circulation.accessible_from.contains(&b.space_type);
    let must_to   = dna[&b.space_type].circulation.accessible_from.contains(&a.space_type);

    match (must_from, must_to) {
        (true, true) => EdgeClass::DirectDoor,
        (true, false) => EdgeClass::DirectedDoor { from: a.id, to: b.id },
        (false, true) => EdgeClass::DirectedDoor { from: b.id, to: a.id },
        (false, false) => EdgeClass::OptionalDoor,
    }
}
```

# 2.7 PASO 2 — ÁRBOL DE CIRCULACIÓN MÍNIMA

## 2.7.1 Objetivo

Encontrar el **subgrafo mínimo** que conecta todos los locales habitables al acceso principal, respetando las relaciones dirigidas.

## 2.7.2 Algoritmo

```rust
fn build_circulation_tree(
    access_graph: &AccessibilityGraph,
    functional_graph: &FunctionalGraph,
    entry_space: Uuid,
) -> CirculationTree {
    // 1. Asignar pesos a aristas
    //    peso bajo = conexión preferida
    //    peso alto  = conexión no preferida
    let weighted = access_graph.edges.iter().map(|e| {
        let w = edge_weight(e, functional_graph);
        (e.from, e.to, w)
    }).collect::<Vec<_>>();

    // 2. Aplicar respeto a relaciones dirigidas
    //    Si a→b es obligatoria, la arista debe usarse
    let mut mandated = Vec::new();
    for edge in &functional_graph.edges {
        if edge.kind == RelationshipKind::MustAccessFrom {
            mandated.push((edge.from, edge.to));
        }
    }

    // 3. Construir MST modificado:
    //    - Incluir mandatos primero
    //    - Completar con aristas de peso mínimo (Kruskal)
    let tree = kruskal_with_mandates(&weighted, &mandated, entry_space);

    // 4. Verificar que todos los habitables están conectados
    let unreachable = tree.unreachable_from(entry_space);
    if !unreachable.is_empty() {
        // Reparar: añadir aristas mínimas para conectar huérfanos
        return repair_circulation(tree, unreachable, access_graph);
    }

    tree
}
```

## 2.7.3 Función `edge_weight`

```rust
fn edge_weight(e: &AccessEdge, fg: &FunctionalGraph) -> f64 {
    let base = 1.0;

    let functional_bonus = fg.edges.iter()
        .filter(|fe| fe.from == e.from && fe.to == e.to)
        .map(|fe| match fe.kind {
            RelationshipKind::RequiredAdjacent   => -0.5,
            RelationshipKind::PreferredAdjacent  => -0.2,
            RelationshipKind::ServiceCluster     => -0.3,
            _ => 0.0,
        })
        .sum::<f64>();

    let privacy_penalty = compute_privacy_penalty(e);

    (base + functional_bonus + privacy_penalty).max(0.1)
}
```

# 2.8 PASO 3 — MATERIALIZAR CORREDORES

## 2.8.1 Objetivo

Convertir aristas del árbol en **geometría real de corredor**.

## 2.8.2 Casos

```text
CASO A  Dos locales comparten pared
        → no hace falta corredor, solo puerta

CASO B  Dos locales no comparten pared, pero están en la misma zona
        → crear corredor interno

CASO C  Dos locales están en zonas distintas
        → crear corredor que atraviese el límite de zona

CASO D  Local rodeado por completo por otros
        → crear corredor perimetral o pasante
```

## 2.8.3 Algoritmo

```rust
fn materialize_corridor(
    from: &SpacePlacement,
    to: &SpacePlacement,
    zone: &ZonePlacement,
    candidates: &[SpacePlacement],
) -> Corridor {
    // 1. Punto de origen y destino
    let p_from = closest_point_on_boundary(&from.polygon, &to.polygon.centroid());
    let p_to = closest_point_on_boundary(&to.polygon, &from.polygon.centroid());

    // 2. Ancho del corredor (según ruleset y uso)
    let width = corridor_width_for(from.space_type, to.space_type);

    // 3. Trazar eje entre p_from y p_to esquivando locales
    let axis = route_axis_avoiding(p_from, p_to, candidates, width);

    // 4. Construir polígono del corredor
    let polygon = build_corridor_polygon(&axis, width);

    Corridor {
        axis,
        polygon,
        width,
        from: from.space_id,
        to: to.space_id,
        length: axis.length(),
    }
}
```

```rust
fn place_door(
    from: &SpacePlacement,
    to: &SpacePlacement,
    dna_from: &SpaceDNA,
    dna_to: &SpaceDNA,
    ruleset: &Ruleset,
) -> Option<Door> {
    // 1. Paredes compartidas
    let shared = shared_walls(&from.polygon, &to.polygon);
    if shared.is_empty() { return None; }

    // 2. Filtrar por longitud mínima
    let usable: Vec<_> = shared.into_iter()
        .filter(|w| w.length >= ruleset.door_min_wall_length(from.space_type, to.space_type))
        .collect();
    if usable.is_empty() { return None; }

    // 3. Elegir la mejor pared
    let best = usable.iter().max_by_key(|w| {
        wall_door_quality(w, from, to, dna_from, dna_to)
    })?;

    // 4. Posición sobre la pared
    let position = door_position_on_wall(best, from, to);

    // 5. Ancho
    let width = ruleset.door_width(from.space_type, to.space_type);

    // 6. Sentido de apertura
    let swing = door_swing_direction(from, to, dna_from, dna_to);

    Some(Door {
        id: Uuid::new_v4(),
        wall_id: best.id,
        position,
        width,
        swing,
        kind: classify_door(from, to),
    })
}
```

## 2.9.4 `wall_door_quality`

```rust
fn wall_door_quality(
    wall: &SharedWall,
    from: &SpacePlacement,
    to: &SpacePlacement,
    dna_from: &SpaceDNA,
    dna_to: &SpaceDNA,
) -> f64 {
    let mut q = 0.0;

    // Preferir paredes céntricas
    q += 0.3 * (1.0 - (wall.center_distance_to(from.polygon.centroid()) / 10.0).min(1.0));

    // Preferir paredes donde hay espacio libre del otro lado
    q += 0.3 * free_space_ratio(wall, from, to);

    // Preferir paredes donde el mobiliario no interfiere
    q += 0.2 * furniture_clearance_score(wall, from, to);

    // Preferir paredes no acústicamente separadas
    if dna_from.acoustic.separated && dna_to.acoustic.separated {
        q -= 0.5;
    }

    q
}
```

```text
Excepciones:
  - baño → siempre abre hacia afuera
  - closet → siempre abre hacia afuera
  - locales con equipamiento crítico → abre hacia afuera
```

```rust
fn place_windows(
    space: &SpacePlacement,
    dna: &SpaceDNA,
    ruleset: &Ruleset,
) -> Vec<Window> {
    let mut windows = Vec::new();

    // 1. Área mínima requerida
    let required = space.area * dna.daylight.min_window_area_ratio;

    // 2. Ordenar bordes exteriores por calidad (orientación + largo + libre)
    let mut edges = space.exterior_edges.clone();
    edges.sort_by_key(|e| std::cmp::Reverse(edge_quality(e, dna, ruleset)));

    // 3. Repartir el área requerida
    let mut remaining = required;
    for edge in edges {
        if remaining <= 0.0 { break; }
        if !is_valid_facade(edge, ruleset) { continue; }

        let avail = edge.length * ruleset.max_window_height_ratio;
        let take = remaining.min(avail);

        let window = build_window(edge, take, dna, ruleset);
        remaining -= window.area();
        windows.push(window);
    }

    // 4. Verificar holgura mínima entre ventanas
    windows = remove_overlapping_windows(windows);

    windows
}
```

* Ventana de baño: parte alta (a partir de 1.20 m).
* Ventana de cocina: sobre lavadero y fregadero.

```rust
fn repair_circulation(
    candidate: &mut Candidate,
    violations: Vec<CirculationViolation>,
    input: &CirculationInput,
) -> RepairResult {
    for _ in 0..MAX_REPAIR_ITERATIONS {
        let current = validate_circulation(candidate)?;
        if current.violations.is_empty() {
            return RepairResult::Success;
        }

        let worst = current.violations.iter()
            .max_by_key(|v| severity_rank(v.severity))
            .unwrap();

        let strategy = select_strategy(worst, candidate, input);
        apply_strategy(candidate, strategy);

        candidate.lineage.push(Decision {
            entity_id: candidate.id,
            rule_or_heuristic: format!("circ_repair:{:?}", strategy),
            explanation: format!("Reparando: {}", worst.message),
            ..
        });
    }

    RepairResult::Partial
}
```

# 3.9 PASO 5 — ACOTAR AUTOMÁTICAMENTE

## 3.9.1 Estrategia

```text
NIVEL 1: cotas parciales externas  (distancias entre ejes de muros)
NIVEL 2: cotas totales externas    (longitud total de fachada)
NIVEL 3: cotas internas por local  (dimensiones útiles)
NIVEL 4: cotas de aberturas        (posición y ancho de puertas y ventanas)
```

## 3.9.2 Algoritmo externo

```rust
fn dimension_exterior(
    building: &Building,
    sheet: &mut Sheet,
    scale: Scale,
) -> Vec<DimensionChain> {
    let mut chains = Vec::new();

    for edge in building.facade_edges() {
        let mut chain = DimensionChain::new(edge, scale);

        // 1. Puntos a acotar
        let points = collect_dimension_points(&edge);

        // 2. Ordenar por posición sobre el borde
        let sorted = sort_along_edge(points, &edge);

        // 3. Crear segmentos
        for i in 0..sorted.len() - 1 {
            chain.add_segment(
                sorted[i],
                sorted[i + 1],
                dimension_text(sorted[i + 1] - sorted[i], scale),
            );
        }

        chains.push(chain);
    }

    chains
}
```

## 3.9.3 Algoritmo interno

```rust
fn dimension_space(
    space: &SpacePlacement,
    sheet: &mut Sheet,
    scale: Scale,
) -> Vec<Dimension> {
    // Cotas internas de dimensiones útiles (sin muros)
    let inner = inset_polygon(&space.polygon, wall_thickness / 2.0);

    let bbox = inner.bounding_box();

    vec![
        Dimension::horizontal(bbox.min.x, bbox.max.x, text = width_m(inner)),
        Dimension::vertical(bbox.min.y, bbox.max.y, text = height_m(inner)),
    ]
}
```

## 3.9.4 Reglas de acotado

* Cotas siempre por fuera del edificio.
* Cotas parciales más cercanas al edificio.
* Cotas totales más alejadas.
* Sin cruces entre líneas de cota.
* Texto siempre horizontal (excepto cotas verticales).
* Texto sobre la línea de cota.
* Flechas normalizadas según estándar del ruleset.

# 3.11 PASO 7 — EJES Y GRILLAS

```rust
fn generate_grids(candidate: &Candidate, sheet: &mut Sheet) {
    // 1. Extraer muros portantes
    let load_bearing = candidate.walls.iter().filter(|w| w.is_load_bearing);

    // 2. Agrupar por alineación
    let x_axes = cluster_by_x(load_bearing);
    let y_axes = cluster_by_y(load_bearing);

    // 3. Etiquetar
    for (i, axis) in x_axes.iter().enumerate() {
        let letter = char::from(b'A' + i as u8);
        sheet.add_grid(Layer::A_GRID, Grid {
            direction: Vertical,
            position: axis.position,
            label: letter.to_string(),
            bubble_top: true,
            bubble_bottom: true,
        });
    }

    for (i, axis) in y_axes.iter().enumerate() {
        sheet.add_grid(Layer::A_GRID, Grid {
            direction: Horizontal,
            position: axis.position,
            label: (i + 1).to_string(),
            bubble_left: true,
            bubble_right: true,
        });
    }
}
```

Reglas:
* Ejes verticales: letras A, B, C…
* Ejes horizontales: números 1, 2, 3…
* Burbujas en los extremos.
* Distancia de burbuja al borde: 1.5 cm en papel.

```rust
pub fn export_pdf(doc: &DocumentationOutput, options: PdfOptions) -> Result<Vec<u8>> {
    let mut pdf = PdfBuilder::new();
    pdf.set_metadata(options.metadata);

    for drawing in &doc.drawings {
        let page = render_drawing_to_page(drawing, options.dpi);
        pdf.add_page(page);
    }

    for schedule in &doc.schedules {
        let page = render_schedule_to_page(schedule);
        pdf.add_page(page);
    }

    if options.include_memory {
        let pages = render_memory(&doc.memory, &options.memory_template);
        for page in pages {
            pdf.add_page(page);
        }
    }

    pdf.build()
}
```

```rust
pub fn export_dxf(drawing: &Drawing) -> Result<String> {
```

# 4.1 PROPÓSITO

Definir el formato estándar, validable y versionable de la **base de conocimiento arquitectónico**: Space DNA, tipologías, heurísticas, rulesets y catálogos.

Todo lo que un arquitecto sabe y puede escribir, vive aquí. Nada de esto vive en el código.

# 4.2 PRINCIPIOS

```text
1. Formato: YAML 1.2
2. Codificación: UTF-8
3. Casing: snake_case para claves, kebab-case para IDs
4. Unidades: métricas (mm, m, m², m³)
5. Idioma: cada archivo declara su idioma base
6. Versionado: semver obligatorio por archivo
7. Validación: schema JSON embebido o referenciado
8. Extensibilidad: campo `x-*` reservado para extensiones
```

## 4.6.2 DSL controlado

El lenguaje de expresión soporta:

```text
Operadores: + - * / % == != < <= > >= && || ! ( )
Cuantificadores: for all, exists, count
Colecciones: [space_id], habitable_spaces, corridors, doors
Funciones: reachable_from, adjacent_to, distance, area, perimeter
Variables: circulación, ratio, lista de parámetros
```

No permite: I/O, acceso a ficheros, llamadas al sistema, ejecución arbitraria.

# 4.9 VALIDACIÓN DE SCHEMAS

## 4.9.1 Validación al cargar

```rust
pub struct KnowledgeLoader {
    schemas: HashMap<String, JsonSchema>,
}

impl KnowledgeLoader {
    pub fn load(&self, path: &Path) -> Result<KnowledgeItem, KnowledgeError> {
        // 1. Leer YAML
        let value: serde_yaml::Value = serde_yaml::from_reader(File::open(path)?)?;

        // 2. Leer $schema
        let schema_uri = value.get("$schema")
            .and_then(|v| v.as_str())
            .ok_or(KnowledgeError::MissingSchema)?;

        // 3. Validar contra schema
        let schema = self.schemas.get(schema_uri)
            .ok_or(KnowledgeError::UnknownSchema(schema_uri.into()))?;

        validate(&value, schema)?;

        // 4. Validaciones semánticas extra
        self.semantic_validate(&value)?;

        // 5. Deserializar al tipo concreto
        deserialize_typed(value)
    }
}
```

## 4.9.2 Validaciones semánticas

```text
- IDs únicos por tipo
- Referencias a otros IDs existentes
- Áreas coherentes: min ≤ pref ≤ max
- Dimensiones positivas
- Unidades coherentes
- Referencias circulares en herencia detectadas
- Versionado semver válido
- Idioma declarado y coherente
```

# 4.10 VERSIONADO Y MIGRACIÓN

## 4.10.1 Versionado semver

* **major:** cambio incompatible (campos eliminados, renombrados)
* **minor:** campos añadidos opcionales
* **patch:** correcciones

## 4.10.2 Migración

```yaml
# knowledge/space_dna/bedroom.yaml
version: "2.0.0"
migrates_from: "1.x"
migration_notes: |
  - Campo `bed_type` eliminado (reemplazado por `furniture.required`)
  - Campo `min_area` renombrado a `area.min`
```

Al cargar un archivo de versión antigua:

```rust
fn migrate(value: Value, target_version: &str) -> Result<Value> {
    let from = value.get("version").and_then(|v| v.as_str());
    match (from, target_version) {
        (Some("1.x"), "2.0") => migrate_1_to_2(value),
        (Some(v), t) if v == t => Ok(value),
        (Some(v), t) => Err(MigrationError::Unsupported(v.into(), t.into())),
        _ => Err(MigrationError::MissingVersion),
    }
}
```

# 4.11 CARGA EN CALIENTE

El sistema permite recargar la base de conocimiento **sin reiniciar**:

```rust
pub fn reload_knowledge(container: &AppContainer) -> Result<ReloadReport> {
    let loader = &container.knowledge_loader;

    // 1. Detectar archivos modificados
    let changed = loader.detect_changes()?;

    // 2. Validar todos antes de aplicar
    for path in &changed {
        loader.validate_only(path)?;
    }

    // 3. Aplicar cambios
    let mut report = ReloadReport::default();
    for path in changed {
        match loader.reload(path) {
            Ok(item) => report.applied.push(item.id),
            Err(e) => report.failed.push((path, e)),
        }
    }

    // 4. Invalidar cachés afectadas
    container.cache.invalidate_by_knowledge(&report.applied);

    // 5. Notificar al frontend
    container.emit_event(KnowledgeReloaded { report: report.clone() })?;

    Ok(report)
}
```

Esto permite al arquitecto **editar un Space DNA en YAML y ver el resultado inmediatamente** en la próxima generación.

Lo que queda por definir para completar la especificación:

1. **Contrato del motor de sitio** — análisis del polígono, orientación, accesos, retiros.
2. **Contrato del motor de programa** — derivación del programa arquitectónico a partir de la descripción.

4. **Contrato del sistema de trazabilidad** — formato de `Decision`, presentación al arquitecto, panel UI.
5. **Contrato del sistema de alternativas** — presentación, comparación, aprobación, cambios.

# 5.5 PASO 1 — LIMPIEZA Y SIMPLIFICACIÓN

## 5.5.1 Objetivo

Convertir el polígono crudo (importado, dibujado o medido) en un `EditablePolygon` limpio, ortorrectificado cuando sea razonable, y apto para operaciones geométricas.

## 5.5.2 Algoritmo

```rust
fn clean_plot(raw: &Polygon, tol: f64) -> EditablePolygon {
    // 1. Eliminar vértices duplicados
    let p1 = remove_duplicate_vertices(raw, 0.01);

    // 2. Eliminar segmentos cero
    let p2 = remove_zero_segments(&p1, 0.01);

    // 3. Simplificar con Douglas-Peucker
    let p3 = douglas_peucker(&p2, tol);

    // 4. Cerrar si está abierto
    let p4 = close_polygon(&p3);

    // 5. Ortorrectificar bordes casi rectos
    let p5 = orthogonalize(&p4, tolerance_deg = 3.0);

    // 6. Corregir autointersecciones
    let p6 = resolve_self_intersections(&p5);

    EditablePolygon::from(p6)
}
```

```rust
fn apply_setbacks(
    polygon: &EditablePolygon,
    accesses: &[AccessPoint],
    ruleset: &Ruleset,
) -> SetbackLines {
    // 1. Determinar qué borde es "frente"
    let front_edge = identify_front_edge(polygon, accesses);

    // 2. Determinar laterales y fondo
    let (left, right, back) = classify_remaining_edges(polygon, front_edge);

    // 3. Aplicar offsets hacia adentro
    SetbackLines {
        front: offset_inward(polygon, front_edge, ruleset.setbacks.front),
        back: offset_inward(polygon, back, ruleset.setbacks.back),
        left: offset_inward(polygon, left, ruleset.setbacks.left),
        right: offset_inward(polygon, right, ruleset.setbacks.right),
        corner_front: None,
        corner_side: None,
    }
}
```

```rust
fn compute_buildable_polygon(
    plot: &EditablePolygon,
    setbacks: &SetbackLines,
) -> EditablePolygon {
    // 1. Construir rectángulo/polígono interno
    let inner = inset_polygon_multi(
        plot,
        &[
            (setbacks.front.edge, setbacks.front.distance),
            (setbacks.back.edge, setbacks.back.distance),
            (setbacks.left.edge, setbacks.left.distance),
            (setbacks.right.edge, setbacks.right.distance),
        ],
    );

    // 2. Corregir si el inset colapsa
    if inner.area() < MIN_BUILDABLE_AREA {
        return report_collapse(plot, setbacks);
    }

    inner
}
```

## 5.8.2 Área y volumen máximo

```rust
fn compute_max_volume(
    buildable: &EditablePolygon,
    ruleset: &Ruleset,
) -> (f64, u32, f64, f64) {
    let footprint = buildable.area();
    let coeff_occupation = ruleset.occupancy.max_occupation_coefficient;
    let coeff_use = ruleset.occupancy.max_floor_area_ratio;

    let max_footprint = footprint.min(coeff_occupation * plot_area);
    let max_built_area = coeff_use * plot_area;
    let max_floors = (max_built_area / max_footprint).floor() as u32;
    let max_height = max_floors as f64 * ruleset.heights.min_floor_height;

    (max_footprint, max_floors, max_height, max_built_area)
}
```

## 5.8.3 Validaciones

* Si `buildable.area < programa.total_area_min` → advertencia crítica.
* Si `max_floors < programa.min_floors` → error.
* Si `buildable` no contiene el acceso principal → advertencia.

# 6.6 PASO 2 — REGLAS DE TIPOLOGÍA

## 6.6.1 Motor de reglas de programa

```rust
fn apply_typology_rules(
    normalized: &NormalizedInput,
    typology: &Typology,
) -> Vec<SpaceRequirement> {
    let mut program = Vec::new();

    // 1. Programa base de la tipología
    for base in &typology.base_program {
        program.push(SpaceRequirement {
            space_type: base.space.clone(),
            count: base.count,
            area_min: base.area_override.unwrap_or(0.0),
            source: RequirementSource::TypologyBase,
            ..
        });
    }

    // 2. Evaluar reglas condicionales
    for rule in &typology.program_rules {
        let ctx = RuleContext::from(normalized);
        if eval_condition(&rule.if_expr, &ctx) {
            apply_consequence(&rule.then_expr, &mut program, &ctx);
        }
    }

    // 3. Añadir mandatorios del usuario
    for space_type in &normalized.mandatory {
        if !program.iter().any(|s| s.space_type == *space_type) {
            program.push(SpaceRequirement {
                space_type: space_type.clone(),
                count: 1,
                source: RequirementSource::UserExplicit,
                ..
            });
        }
    }

    // 4. Eliminar prohibidos
    program.retain(|s| !normalized.forbidden.contains(&s.space_type));

    program
}
```

```rust
fn unify_duplicates(program: Vec<SpaceRequirement>) -> Vec<SpaceRequirement> {
    let mut by_type: HashMap<SpaceType, Vec<SpaceRequirement>> = group_by_type(program);
```

```rust
fn fit_to_target_area(
    program: &mut Vec<SpaceRequirement>,
    target: f64,
) {
    let current: f64 = program.iter().map(|r| r.area_pref * r.count as f64).sum();
    let factor = target / current;

    for req in program {
        // Aplicar factor con límites del DNA
        req.area_pref = (req.area_pref * factor).clamp(req.area_min, req.area_max);
    }

    // Recalcular y reportar desviación
    let final_area: f64 = program.iter().map(|r| r.area_pref * r.count as f64).sum();
    if (final_area - target).abs() / target > 0.10 {
        warn!("No se puede alcanzar el área objetivo: {final_area} vs {target}");
    }
}
```

## 6.8.2 Reglas de coherencia

```rust
fn check_coherence(program: &ArchitecturalProgram, site: &SiteAnalysis) -> Vec<ProgramWarning> {
    let mut warnings = Vec::new();

    // Baños vs dormitorios
    let beds = program.count_of(SpaceType::Bedroom);
    let baths = program.count_of(SpaceType::Bathroom);
    if beds >= 3 && baths < 2 {
        warnings.push(ProgramWarning::InsufficientBathrooms { beds, baths });
    }

    // Área total vs área edificable
    if program.total_area_min > site.max_built_area * 0.95 {
        warnings.push(ProgramWarning::ProgramTooLarge {
            program_min: program.total_area_min,
            site_max: site.max_built_area,
        });
    }

    // Locales obligatorios de la tipología
    for required in program.typology.required_spaces() {
        if !program.has(required) {
            warnings.push(ProgramWarning::MissingRequired { space: required });
        }
    }

    warnings
}
```

## 6.8.3 Resolución de conflictos

Si hay `ProgramWarning::ProgramTooLarge`, se ofrece al usuario:

1. Reducir programa
2. Aumentar plantas
3. Reducir áreas mínimas
4. Cambiar tipología

El motor **no decide solo**. Propone y el usuario aprueba.

## 6.9.1 Construcción del grafo

```rust
fn build_functional_graph(
    program: &ArchitecturalProgram,
    typology: &Typology,
    dna: &HashMap<SpaceType, SpaceDNA>,
) -> FunctionalGraph {
    let mut graph = FunctionalGraph::new();

    // 1. Añadir nodos
    for req in &program.spaces {
        graph.add_node(req.id);
    }

    // 2. Aristas de tipología
    for (from_type, rel) in &typology.relationships {
        for to_type in &rel.connected_to {
            graph.add_edge(
                program.ids_of(from_type),
                program.ids_of(to_type),
                RelationshipKind::MustAccessFrom,
                weight = 1.0,
            );
        }
        for to_type in &rel.adjacent_to {
            graph.add_edge(
                program.ids_of(from_type),
                program.ids_of(to_type),
                RelationshipKind::RequiredAdjacent,
                weight = 0.9,
            );
        }
        for to_type in &rel.not_adjacent_to {
            graph.add_edge(
                program.ids_of(from_type),
                program.ids_of(to_type),
                RelationshipKind::AcousticSeparation,
                weight = 0.8,
            );
        }
    }

    // 3. Aristas del Space DNA
    for req in &program.spaces {
        let d = &dna[&req.space_type];

        for to_type in &d.adjacency.required {
            graph.add_edge(req.id, program.ids_of(to_type), RequiredAdjacent, 1.0);
        }
        for to_type in &d.adjacency.preferred {
            graph.add_edge(req.id, program.ids_of(to_type), PreferredAdjacent, 0.5);
        }
        for to_type in &d.adjacency.avoided {
            graph.add_edge(req.id, program.ids_of(to_type), AcousticSeparation, 0.7);
        }
        for to_type in &d.adjacency.forbidden {
            graph.add_edge(req.id, program.ids_of(to_type), ForbiddenAdjacency, 1.0);
        }
    }

    graph
}
```

```rust
fn assign_zones(
    program: &ArchitecturalProgram,
    typology: &Typology,
    dna: &HashMap<SpaceType, SpaceDNA>,
) -> HashMap<ZoneKind, Vec<Uuid>> {
    let mut zones = HashMap::new();

    for req in &program.spaces {
        let zone = typology.zone_of(&req.space_type)
            .or_else(|| dna[&req.space_type].zone())
            .unwrap_or(ZoneKind::Circulation);

        zones.entry(zone).or_insert_with(Vec::new).push(req.id);
    }

    zones
}
```

# 7.5 ESTRATEGIAS DE ZONIFICACIÓN

Se generan esquemas por **combinación de 3 estrategias**:

## 7.5.1 Estrategia A — Slicing paralelo

Cortes paralelos al frente, en orden de profundidad:

```text
[frente]
  PÚBLICA
  CIRCULACIÓN
  SERVICIO
  PRIVADA
[fondo]
```

Ventajoso en parcelas rectangulares profundas.

## 7.5.2 Estrategia B — Slicing perpendicular

Cortes perpendiculares al frente, en columnas:

```text
[frente]
  PÚBLICA  │  CIRCULACIÓN  │  SERVICIO  │  PRIVADA
[fondo]
```

Ventajoso en parcelas anchas y poco profundas.

## 7.5.3 Estrategia C — Núcleo y satélites

CIRCULACIÓN al centro; zonas alrededor:

```text
       PÚBLICA
         │
SERVICIO─┼─PRIVADA
         │
      TÉCNICA
```

Ventajoso cuando la circulación es densa o el polígono es irregular.

## 7.5.4 Estrategia D — Frente/fondo con servicio lateral

PÚBLICA al frente, PRIVADA al fondo, SERVICIO en un lateral:

```text
[frente]
  PÚBLICA
  ─────────
  SERVICIO │ PRIVADA
[fondo]
```

Variante común en viviendas urbanas.

## 7.5.5 Estrategia E — Patio central

Cuando el programa lo justifica (clima cálido), PRIVADA rodea un patio:

```text
    PÚBLICA
  ┌────────┐
  │  PATIO │  PRIVADA
  └────────┘
    SERVICIO
```

# 7.6 ALGORITMO PRINCIPAL

```rust
pub fn generate_zoning(input: ZoningInput) -> ZoningOutput {
    let mut rng = SmallRng::seed_from_u64(input.options.seed);

    // 1. Calcular proporciones de cada zona
    let proportions = compute_zone_proportions(&input);

    // 2. Generar esquemas por estrategia
    let mut schemes = Vec::new();

    schemes.extend(scheme_slicing_parallel(&input, &proportions, &mut rng));
    schemes.extend(scheme_slicing_perpendicular(&input, &proportions, &mut rng));
    schemes.extend(scheme_core_satellite(&input, &proportions, &mut rng));
    schemes.extend(scheme_front_back_lateral(&input, &proportions, &mut rng));
    if is_patio_applicable(&input) {
        schemes.extend(scheme_patio(&input, &proportions, &mut rng));
    }

    // 3. Evaluar cada esquema
    for scheme in &mut schemes {
        scheme.quality_score = evaluate_zoning(scheme, &input);
    }

    // 4. Ordenar por calidad
    schemes.sort_by(|a, b| b.quality_score.overall.partial_cmp(&a.quality_score.overall).unwrap());

    // 5. Truncar a las mejores N
    schemes.truncate(input.options.max_alternatives);

    ZoningOutput {
        schemes: schemes.clone(),
        selected: schemes.first().map(|s| s.id).unwrap(),
        decisions: collect_decisions(&schemes),
    }
}
```

# 7.7 CÁLCULO DE PROPORCIONES

```rust
fn compute_zone_proportions(input: &ZoningInput) -> HashMap<ZoneKind, f64> {
    let mut area_by_zone: HashMap<ZoneKind, f64> = HashMap::new();

    for req in &input.program.spaces {
        let zone = input.typology.zone_of(&req.space_type).unwrap();
        let area = req.area_pref * req.count as f64;
        *area_by_zone.entry(zone).or_insert(0.0) += area;
    }

    let total: f64 = area_by_zone.values().sum();

    area_by_zone.into_iter()
        .map(|(k, v)| (k, v / total))
        .collect()
}
```

# 7.8 ESQUEMA — SLICING PARALELO

```rust
fn scheme_slicing_parallel(
    input: &ZoningInput,
    proportions: &HashMap<ZoneKind, f64>,
    rng: &mut SmallRng,
) -> Vec<ZoningScheme> {
    let buildable = input.buildable;
    let front_edge = identify_front_edge(buildable, &input.site.accesses);

    // Orden de zonas de frente a fondo
    let mut order = vec![ZoneKind::Public, ZoneKind::Circulation, ZoneKind::Service, ZoneKind::Private];

    // Variaciones: probar órdenes alternativos
    let variations = vec![
        order.clone(),
        swap(&order, 2, 3),                     // Service antes de Circulation
        vec![Public, Service, Circulation, Private],
        vec![Public, Circulation, Private, Service],
    ];

    let mut schemes = Vec::new();
    for ordered in variations {
        let scheme = apply_parallel_slices(buildable, &ordered, proportions, front_edge);
        schemes.push(scheme);
    }

    schemes
}
```

## 7.8.1 Aplicación de cortes

```rust
fn apply_parallel_slices(
    polygon: &EditablePolygon,
    order: &[ZoneKind],
    proportions: &HashMap<ZoneKind, f64>,
    front_edge: EdgeRef,
) -> ZoningScheme {
    let mut remaining = polygon.clone();
    let mut placements = Vec::new();

    for (i, zone) in order.iter().enumerate() {
        let is_last = i == order.len() - 1;
        if is_last {
            placements.push(ZonePlacement {
                kind: *zone,
                polygon: remaining.clone(),
                ..
            });
            break;
        }

        let ratio = proportions.get(zone).copied().unwrap_or(0.0)
            / proportions.iter()
                .filter(|(k, _)| order[i..].contains(k))
                .map(|(_, v)| v).sum::<f64>();

        let (front, back) = slice_polygon_from_edge(&remaining, front_edge, ratio);

        placements.push(ZonePlacement {
            kind: *zone,
            polygon: front,
            ..
        });
        remaining = back;
    }

    ZoningScheme {
        id: Uuid::new_v4(),
        zones: placements,
        ..
    }
}
```

# 7.9 EVALUACIÓN DEL ESQUEMA

```rust
pub struct ZoningScore {
    pub zone_connectivity: f64,     // qué tan bien conectadas están las zonas
    pub circulation_efficiency: f64, // circulación implícita entre zonas
    pub orientation_quality: f64,   // zonas en orientación adecuada
    pub constructability: f64,      // simplicidad estructural
    pub area_fidelity: f64,         // coincidencia con proporciones objetivo
    pub overall: f64,
}

fn evaluate_zoning(scheme: &ZoningScheme, input: &ZoningInput) -> ZoningScore {
    let mut score = ZoningScore::default();

    // 1. Conectividad: zonas deben ser adyacentes según grafo de zonas
    score.zone_connectivity = eval_zone_connectivity(scheme, input);

    // 2. Circulación implícita: zonas que requieren comunicación deben ser contiguas
    score.circulation_efficiency = eval_circulation_zoning(scheme, input);

    // 3. Orientación: Public → sur, Private → este, Service → oeste
    score.orientation_quality = eval_orientation(scheme, input);

    // 4. Constructabilidad: preferir formas ortogonales
    score.constructability = eval_orthogonality(scheme);

    // 5. Fidelidad de área: qué tan cerca están los ratios reales de los objetivo
    score.area_fidelity = eval_area_fidelity(scheme, input);

    score.overall = 0.25 * score.zone_connectivity
        + 0.25 * score.circulation_efficiency
        + 0.20 * score.orientation_quality
        + 0.15 * score.constructability
        + 0.15 * score.area_fidelity;

    score
}
```

```text
3. Toda decisión es inmutable (append-only log).
4. Toda decisión puede consultarse desde la UI.
```

```rust
pub struct DecisionLog {
    entries: Vec<Decision>,
    by_entity: HashMap<Uuid, Vec<usize>>,
    by_kind: HashMap<DecisionKind, Vec<usize>>,
    by_step: BTreeMap<u32, Vec<usize>>,
}

impl DecisionLog {
    pub fn record(&mut self, decision: Decision) {
        let idx = self.entries.len();
        self.by_entity.entry(decision.entity_id).or_default().push(idx);
        self.by_kind.entry(decision.decision_kind).or_default().push(idx);
        self.by_step.entry(decision.generation_step).or_default().push(idx);
        self.entries.push(decision);
    }

    pub fn decisions_for(&self, entity_id: Uuid) -> impl Iterator<Item = &Decision> {
        self.by_entity.get(&entity_id).into_iter().flatten()
            .map(|i| &self.entries[*i])
    }

    pub fn decisions_by_kind(&self, kind: DecisionKind) -> impl Iterator<Item = &Decision> {
        self.by_kind.get(&kind).into_iter().flatten()
            .map(|i| &self.entries[*i])
    }
}
```

```bash
arqgen replay --project proyecto.arqgen --seed 1234567 --candidate 42
```

El sistema re-ejecuta el pipeline con la misma semilla y compara el `DecisionLog` producido con el original. Si difiere, hay un bug.

```rust
fn label_alternative(alt: &Candidate, others: &[Candidate]) -> (String, String) {
    let profile = profile_of(alt.score, others);

    let label = match profile.dominant_trait {
        DominantTrait::Compact => "Compacta",
        DominantTrait::Bright => "Luminosa",
        DominantTrait::Ventilated => "Ventilada",
        DominantTrait::Efficient => "Eficiente",
        DominantTrait::Balanced => "Equilibrada",
        DominantTrait::Spacious => "Amplia",
    };

    let subtitle = match profile.secondary_trait {
        Some(DominantTrait::Economic) => "y económica",
        Some(DominantTrait::Bright) => "y luminosa",
        Some(DominantTrait::Ventilated) => "y bien ventilada",
        Some(DominantTrait::Balanced) => "y equilibrada",
        _ => "",
    };

    (format!("{} {}", label, subtitle), subtitle.into())
}
```

## 9.4.1 Perfil de traits

```rust
pub struct AlternativeProfile {
    pub dominant_trait: DominantTrait,
    pub secondary_trait: Option<DominantTrait>,
    pub percentile_ranks: HashMap<String, f64>,
}

fn profile_of(score: EvaluationScore, others: &[Candidate]) -> AlternativeProfile {
    // Calcular percentiles de cada criterio
    let pr_area = percentile_rank(score.area_compliance, others, |s| s.area_compliance);
    let pr_daylight = percentile_rank(score.daylight_score, others, |s| s.daylight_score);
    let pr_vent = percentile_rank(score.ventilation_score, others, |s| s.ventilation_score);
    let pr_compact = percentile_rank(score.compactness_score, others, |s| s.compactness_score);
    let pr_struct = percentile_rank(score.structure_economy_score, others, |s| s.structure_economy_score);

    // Determinar trait dominante
    let mut traits = vec![
        (DominantTrait::Compact, pr_compact),
        (DominantTrait::Bright, pr_daylight),
        (DominantTrait::Ventilated, pr_vent),
        (DominantTrait::Efficient, pr_struct),
        (DominantTrait::Balanced, average_of_all(&score)),
    ];

    traits.sort_by(|a, b| b.1.partial_cmp(&a.1).unwrap());

    AlternativeProfile {
        dominant_trait: traits[0].0,
        secondary_trait: if traits[1].1 > 0.7 { Some(traits[1].0) } else { None },
        percentile_ranks: hashmap![
            "daylight" => pr_daylight,
            "compactness" => pr_compact,
            "structure" => pr_struct,
        ],
    }
}
```

```rust
fn strengths_and_weaknesses(alt: &Candidate, others: &[Candidate]) -> (Vec<String>, Vec<String>) {
    let mut strengths = Vec::new();
    let mut weaknesses = Vec::new();

    let prs = percentiles_against(alt, others);

    for (criterion, pr) in prs {
        if pr > 0.80 {
            strengths.push(describe_strength(criterion, &alt.score));
        } else if pr < 0.20 {
            weaknesses.push(describe_weakness(criterion, &alt.score));
        }
    }

    (strengths, weaknesses)
}
```

## 9.5.4 Tradeoffs

```rust
fn tradeoffs(alt: &Candidate, others: &[Candidate], program: &ArchitecturalProgram) -> String {
    let mut text = String::new();

    // Comparar con cada otra alternativa
    for other in others {
        if other.id == alt.id { continue; }

        let diffs = diff_score(&alt.score, &other.score);
        if diffs.is_empty() { continue; }

        text.push_str(&format!(
            "Frente a {}, esta alternativa {}. ",
            other.label,
            describe_differences(&diffs)
        ));
    }

    text
}
```

# 9.7 RECOMENDACIÓN

El motor puede sugerir una alternativa **sin imponerla**:

```rust
fn recommendation(
    alternatives: &[Alternative],
    priorities: &[ProgramPriority],
) -> Option<Uuid> {
    // Si hay prioridades declaradas, ponderar según ellas
    if !priorities.is_empty() {
        let best = alternatives.iter().max_by(|a, b| {
            priority_score(&a.score, priorities)
                .partial_cmp(&priority_score(&b.score, priorities))
                .unwrap()
        });
        return Some(best.id);
    }

    // Si no, no recomendar (dejar al arquitecto decidir)
    None
}
```

Cuando no hay prioridades, el sistema **no recomienda**. Presenta las tres y deja decidir.

## 9.8.1 Flujo

```text
1. Sistema presenta 3 alternativas
2. Arquitecto:
   - Aprueba una → pasa a desarrollo
   - Pide ajustes → regeneración guiada
   - Rechaza todas → vuelve a programa
```

## 9.8.2 Regeneración guiada

Cuando el arquitecto pide ajustes, se añaden **restricciones duras** al input de generación:

```rust
fn regenerate_with_adjustments(
    base_input: LayoutInput,
    adjustments: &[Adjustment],
) -> LayoutInput {
    let mut new_input = base_input.clone();

    for adj in adjustments {
        match adj.kind {
            AdjustmentKind::ForceAdjacency(a, b) => {
                new_input.functional_graph.add_mandate(a, b, RequiredAdjacent);
            }
            AdjustmentKind::ForbidAdjacency(a, b) => {
                new_input.functional_graph.add_forbidden(a, b);
            }
            AdjustmentKind::MoveSpace(id, point) => {
                new_input.pinned_positions.insert(id, point);
            }
            AdjustmentKind::ResizeSpace(id, area) => {
                new_input.pinned_areas.insert(id, area);
            }
            AdjustmentKind::ForceOrientation(id, o) => {
                new_input.pinned_orientations.insert(id, o);
            }
            AdjustmentKind::AddSpace(t) => {
                new_input.program.spaces.push(default_requirement(t));
            }
            AdjustmentKind::RemoveSpace(id) => {
                new_input.program.spaces.retain(|s| s.id != id);
            }
        }
    }

    new_input.seed += 1;  // nueva semilla para variación
    new_input
}
```

Las restricciones del usuario **se respetan obligatoriamente** en la regeneración.

# SIGUIENTE PASO PRÁCTICO

Con la especificación completa, el siguiente paso real es **empezar a implementar**. El orden recomendado:

1. **Fase 01–03:** Tauri shell + Rust core + SQLite con migraciones.
2. **Fase 04–07:** geometría 2D, sitio, programa, carga de YAML.
3. **Fase 08–12:** reglas, zonificación, layout (squarified treemap primero).
4. **Fase 13–15:** circulación, aperturas, mobiliario.
5. **Fase 16–18:** evaluación, refinamiento, alternativas.
6. **Fase 19–33:** UI + documentación + exportación + trazabilidad.

**Corte crítico:** terminar la fase 18 y validar con un caso real. Antes de eso, ningún otro documento ni módulo tiene sentido.
