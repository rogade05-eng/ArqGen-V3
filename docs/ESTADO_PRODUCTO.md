# ARQ GEN · Estado verificable frente a «terminado»

**Fecha base:** 2026-09-26. Esta tabla separa el **prototipo ejecutable MVP-0.20** de los [criterios de «núcleo terminado»](../ARQ%20GEN%20TAURI.txt) de la visión v3.0. «Pasa el prototipo» nunca equivale a cumplimiento de normativa o seguridad de obra. Contrato del motor: [MVP-0.20](CONTRATO_MVP20.md); cartera e historial [MVP-0.19](CONTRATO_MVP19.md), geometría v8 de [MVP-0.18](CONTRATO_MVP18.md).

**Adición de presentación 2026-09-29:** [primer paquete de tres láminas SVG A3 de vivienda](CONTRATO_LAMINAS_SVG_V1.md), generado en la web desde una alternativa **ya validada por Rust** y descargable como ZIP con origen v8 reabrible. No se cambió el WASM ni se añadió geometría, plantas superiores, cortes, alzados o nuevas tipologías. El usuario confirmó **hospitales y hoteles como tipologías futuras funcionales**; requieren programas, geometría multinivel, validaciones y fuentes aplicables independientes, no solo mejorar el SVG.

**Adición geométrica 2026-09-30:** [paquete SVG v2](CONTRATO_LAMINAS_SVG_V2.md) con **cuarta hoja A3** y `nivel-0-2d.json`: huella bruta en un solo polígono cotejada con las celdas/área Rust, longitudes de borde y entrada/ventanas sobre el contorno del propio local. Rechaza solapes, patios/partes separadas y vanos incoherentes en lugar de inventar un alzado. Es un derivado web 2D **sin cota Z**; v8, Rust y WASM permanecen intactos. Hospital, hotel y QA Windows siguen pendientes.

## Bloqueos que ningún ejemplo hipotético resuelve

- **Ventilación real:** datos verificables de un equipo identificado y su curva ensayada; red instalable 3D, secciones reales, accesorios y aire de reposición; cálculo de punto de operación y medición/puesta en marcha. El motor actual **no** entrega ni predice caudal entregado, y no debe afirmarlo.
- **Regulación y seguridad:** se [inventariaron 12 PDF aportados](AUDITORIA_FUENTES_CUBA.md) sin convertirlos en reglas. **NC 598:2009** solo es candidata *condicional* para sanitarios de vivienda social urbana; precisa confirmar vigencia y revisar sus referencias: hay enlaces de terceros a NC 337 y NC 391-1/-2, pero no ejemplares oficiales confirmados ni vigencia o derechos verificados. La norma `NC 624` es de seguridad CCTV y las ordenanzas de «Arquitectura y urbanismo» corresponden a **Quito**, no a Cuba. Accesibilidad, evacuación, estructura, salubridad, electricidad y protección contra incendios requieren fuentes aplicables y revisión profesional. El JSON demo **no es** un ruleset legal; sus baños ahora tienen un vano 2D de objetivo 5 % **inventado para la demo, no derivado de NC 598 §8.1**, sin acreditar iluminación natural efectiva. El panel, el aviso de inviabilidad y la ficha del [MVP-0.18](CONTRATO_MVP18.md) muestran **contexto, contorno y trazado frontal (recto o con dos giros) autodeclarados, más hasta dos zonas voluntarias; todo sin verificar**; ámbito y luz permanecen `not_evaluated`, igual que conexión vial, derecho de paso y accesibilidad en `site_approach`. Ni siquiera la declaración «Cuba + vivienda social urbana» o un rodeo despejado en el dibujo determina aplicabilidad, titularidad, acceso real o cumplimiento.
- **Producto desktop:** existe una [estructura Tauri 2 experimental](DESKTOP_EXPERIMENTAL.md) para **Windows/WebView2**, con recursos web locales, CSP y ninguna capability/IPC. Se preparó un [harness WebDriver nativo + workflow Windows](QA_WINDOWS_WEBVIEW2.md) que falla fuera de Windows y un [empaquetador para EXE release en ZIP](COMPILACION_WINDOWS_ZIP.md), pero **no se ha ejecutado ni compilado el shell Tauri en Windows** ni se generó un ZIP de ese shell: Wine/Rust faltan aquí y no se ha ejecutado el runner Windows de GitHub Actions (poder hacer `git push` a la rama no equivale a poder ejecutar ese workflow). Existe por separado un [EXE Zig con navegador externo](EXE_ALTERNATIVO_ZIG.md), compilado como PE Windows pero **no ejecutado en Windows ni equivalente a Tauri/WebView2**. No hay instalador validado ni SQLite. La cartera y el deshacer de corridas son web/IndexedDB o memoria de pestaña, respectivamente; no son un expediente profesional ni edición granular.
- **Alcance generativo maestro:** programa derivado, sitios reales no rectangulares **más allá de dos recortes posteriores opuestos en una caja esquemática**, accesos reales o rutas distintas de un único rodeo 2D de dos giros, zonificación amplia, ocho criterios y refinamiento convergente, planos acotados y documentación profesional todavía requieren contratos y pruebas antes de afirmar cierre. La [lectura de las 11 imágenes añadidas a `main`](OBJETIVO_VISUAL_VARIANTES_PLANOS.md) precisa la meta de familias espaciales realmente distintas y láminas/vistas coherentes, sin confundir esos ejemplos con capacidades presentes o normas.

## Criterio de salida honesto

El **flujo del prototipo** puede probarse en CLI y web: encargo/contexto/croquis 2D → 48 intentos por corrida o barrido optativo de 2–12 semillas (hasta 576 intentos) → validación de huella y trazado declarado → Pareto **solo entre variantes validadas del lote** → hasta tres croquis conceptuales → SVG/JSON/ficha individual, cuaderno de hipótesis, **cartera con respaldo/replay** e historial de la pestaña. Para MVP-0.20 `cargo fmt --all -- --check`, `cargo test --offline --locked --workspace` (**78/78**), `npm ci --prefix web`, `npm test --prefix web` (**71/71**) y `npm run build --prefix web` pasaron. Cuatro SHA-256 de respuestas individuales anteriores al refactor coinciden; la versión v8 individual se mantiene y el lote es un formato aparte. El build offline precarga **cinco archivos** (incluido el worker) y **4/4 E2E** en Chromium headless/Linux comprobaron cancelación, rechazo de lote adulterado, importación íntegra offline y los flujos previos de proyectos, historial y recarga sin red. Chromium/librerías NSS y Rust 1.88/target WASM se prepararon temporalmente desde empaquetadores terceros **fuera de Git**; ello no acredita autenticidad oficial de esos binarios. Siguen pendientes ensayos de recuperación/cuotas, historial durable, compilación/QA nativo Tauri/Windows (WebView2, descargas, persistencia, instalador offline y firma) y revisión profesional. No se ha probado cumplimiento cubano, linderos/acceso real, ventilación ni el producto maestro de la sección 29; ningún croquis habilita obra.

**Decisiones del usuario:** «terminado» significa el **producto maestro completo**, con **Cuba** como jurisdicción objetivo; **no** se dispone por ahora de fichas de equipos. No se interpretan estas decisiones como fuentes normativas ni datos de fabricante. Para poder prometer ese cierre faltan fuentes cubanas trazables y revisión profesional, fichas/curvas verificables para ventilación, desarrollo de los módulos restantes, datos y ensayos de casos reales, QA nativo de Windows e instalador firmado. Hasta entonces deben conservarse `not_evaluated`, `illustrative_not_certified` y el rechazo de alternativas inviables. Los nuevos cortes no se presentarán como cumplimiento ni como fin del proyecto.
