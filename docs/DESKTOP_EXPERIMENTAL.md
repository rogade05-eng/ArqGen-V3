# Tauri 2/Windows: estructura experimental, sin entrega nativa

**Decisión de alcance confirmada:** la meta solicitada es el **producto maestro completo**, para **Cuba**, sobre **Windows/WebView2**. No se dispone aún de fichas verificables de extractores. El prototipo debe seguir mostrando `ventilation_status: "not_evaluated"` y ninguna pantalla, TXT, SVG ni instalador debe atribuir cumplimiento normativo o caudal entregado. Véase [estado del producto](ESTADO_PRODUCTO.md).

## Implementado y aislado

`web/src-tauri/` es una aplicación Tauri 2 **mínima** que pretende incorporar `dist/web/` (HTML, CSS, JS y el mismo WASM de Rust usado en navegador). El proyecto Cargo está aislado del workspace del núcleo para que `cargo test --offline --workspace` continúe funcionando sin descargar Tauri. `web/src-tauri/tauri.conf.json` configura una única ventana local, CSP restringida, `withGlobalTauri: false`, **ninguna capability/IPC**, ni plugins de filesystem, shell o HTTP; no se registran comandos `invoke`. El navegador conserva importación/exportación estándar, la copia rápida optativa IndexedDB de una ranura y la [cartera de hasta ocho proyectos](CONTRATO_MVP19.md) con respaldo JSON y replay (origen distinto al de la web: las copias no se transfieren automáticamente). También ofrece 12 puntos de deshacer/rehacer **solo en memoria**, sin historial durable. Desde [MVP-0.20](CONTRATO_MVP20.md), el mismo bundle incluye un **Web Worker** para explorar hasta 12 semillas con el WASM y cancelarlo sin bloquear la vista; el lote se exporta como JSON separado y no se guarda en IndexedDB. En la vista empaquetada se omite registrar el service worker porque los recursos ya van incluidos. El worker, su carga por el protocolo Tauri y la CSP **no se han verificado en WebView2 nativo**.

El icono `web/src-tauri/icons/` es un **sustituto de prototipo** (PNG/ICO de 8 bits) que debe reemplazarse por un icono diseñado y revisado antes de cualquier distribución.

El bundle está configurado para **NSIS/Windows** y `bundle.windows.webviewInstallMode: "offlineInstaller"`, evitando que *instalar* WebView2 dependa de internet cuando no está presente. **Compilar** sí puede requerir acceso a crates/paquetes e incorporar el redistribuible WebView2; no se incluye ningún runtime externo en Git. No se configura firma de código: un binario sin firma **no** sería apto como distribución profesional. No hay sidecar Python, SQLite, persistencia nativa, edición fina ni documentos de obra todavía.

## Cómo verificarlo en Windows (pendiente)

Existe ahora un [harness nativo y workflow Windows/WebView2](QA_WINDOWS_WEBVIEW2.md) para ejecutar el `.exe` Tauri real vía tauri-driver + EdgeDriver, con fallo obligatorio fuera de Windows y perfil de prueba aislado; **el harness todavía no se ha ejecutado en Windows**. El [empaquetador de EXE Tauri release en ZIP](COMPILACION_WINDOWS_ZIP.md) también está preparado, pero **no existe un binario ni ZIP Tauri reales**: el Rust/WASM temporal usado para la web **no** incluye target MSVC, SDK Windows ni el entorno WebView2 necesario. La web 0.22 y el WASM Rust se recompilaron con toolchain temporal fuera de Git. Hay una [alternativa Zig/navegador externo 0.22 compilada](EXE_ALTERNATIVO_ZIG.md), diferente de Tauri y aún sin ejecutar en Windows. Los tests simulados del transporte en Linux no son QA del shell. El workflow también intenta construir NSIS, pero ni siquiera un build exitoso comprobaría la instalación sin red. No se ha observado un resultado del workflow Windows/Actions para este incremento; un `git push` no constituye aprobación WebView2.

1. Instalar **Rust estable compatible con Tauri 2 (al menos 1.88 para el núcleo)** con el objetivo `wasm32-unknown-unknown`, Node.js/npm y herramientas MSVC de C++ para escritorio. Usar una estación Windows con recursos para compilar Tauri y construir el instalador.
2. Ejecutar desde la raíz: `npm ci --prefix web`, `cargo test --offline --workspace`, `npm test --prefix web`, el [build debug y test `npm run test:webview2 --prefix web`](QA_WINDOWS_WEBVIEW2.md), `npm run tauri --prefix web -- dev` y `npm run tauri --prefix web -- build`. El hook `beforeBuildCommand` recompila el WASM y la web; en desarrollo, si cambia Rust, ejecutar previamente `npm run build:core --prefix web`.
3. En **WebView2 real**, probar respuesta Rust/WASM, CSP sin errores, entrada **v8** con contorno rectangular, un recorte posterior o **dos recortes opuestos** (8 vértices): área demo, diferencia de lado y franja posterior ≥1 m; dos recortes del mismo lado, suma de anchos casi inválida e invasión positiva diminuta rechazados. Probar hasta **dos** reservas voluntarias disjuntas, incluyendo contacto de la segunda con el segundo recorte y bloqueo de huella, franja frontal recta o cualquiera de las tres bandas del rodeo de dos giros; un trazado bloqueado queda sin plano ni SVG. Verificar campos A/B de recortes y zonas, eco del polígono, ficha y motivos sin atribuciones de calle, accesibilidad ni derechos; importar v8 adulterado y rechazar v7 sin migración; descargar ficha/SVG/JSON, guardar/reabrir la copia rápida IndexedDB **v8** y la cartera multiencargo (backup/replay íntegro, conflicto entre pestañas, cuota, importación atómica); comprobar los 12 puntos de deshacer/rehacer en memoria; ejecutar/cancelar el lote multisemilla desde el worker, exportarlo e importarlo adulterado/íntegro con replay fuera de línea bajo la CSP y protocolo Tauri; declarar todas las cotas Z de L0 sin valores por defecto, rechazar un JSON Z adulterado, reabrir el íntegro por separado tras Rust y confirmar que la cartera v8 no guarda esas hipótesis; y reiniciar completamente sin conexión. En instalación limpia y sin red, verificar que NSIS despliega WebView2 desde el instalador offline. Medir rendimiento en hardware objetivo, inspeccionar superficie IPC y firma del paquete.

En Linux se comprobaron la configuración estática del bundle mediante pruebas JS, la paridad CLI↔WASM y el build web; **5/5 E2E en Chromium headless/Linux** pasaron ahora (incluyen Z, worker cancelable, replay de lote offline, copia, cartera, historial y recarga), pero no ejecutan Tauri ni WebView2. El manifiesto Cargo mediante `cargo metadata --no-deps` y el parseo de config por `tauri info` fueron comprobaciones anteriores, **no un build nativo del shell para este corte**. **El entorno Linux carece de WebKitGTK/rsvg y no es Windows**: no se ha compilado ni ejecutado Tauri nativamente, ni se ha producido/validado instalador. `cargo generate-lockfile` del shell sigue bloqueado aquí por fallo TLS contra `index.crates.io`. El runner Windows sí resolvió dependencias y mostró el motivo del bloqueo: **`tauri 2.11.5` no publica su `Cargo.lock`, y una resolución nueva elige versiones incompatibles de su propio árbol** (fallo con `UnexpectedMenuKind` de la macro de `muda` y con `Option<Monitor>` frente a `Result<_, Error>`). `web/src-tauri/Cargo.toml` ahora fija las versiones probadas por el repositorio de Tauri en la etiqueta `tauri-v2.11.5` (`muda 0.19.1`, `tao 0.35.0`, `wry 0.55.0`, `tauri-runtime 2.11.3`, `tauri-runtime-wry 2.11.4`, `tauri-macros 2.6.3`, `tauri-utils 2.9.3`), con una prueba que lo verifica. Falta generar, auditar y versionar el `Cargo.lock` completo antes de distribuir. La prueba del shell y del instalador queda **abierta** y no se contará como criterio cumplido.
