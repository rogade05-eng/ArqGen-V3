# Contrato correctivo — MVP-0.20: exploración multisemilla acotada en Rust

**Estado:** implementado el 2026-09-26, después de [MVP-0.19](CONTRATO_MVP19.md). Es un salto en la **amplitud y trazabilidad de la búsqueda**, no en geometría de parcela, reglas cubanas ni cálculo de ventilación. Rust crate `0.16.0`, web/shell experimental `0.21.0`. La **entrada individual v8, su respuesta y `engine_version: "mvp0.18-rust-0.15.0"` permanecen exactamente iguales**, para que copias v8 previas sigan pudiendo reproducirse. Se añadieron un endpoint/binary y un formato de lote **independientes**; no se amplió el ruleset demo ni la cartera.

## Algoritmo y afirmaciones admisibles

- `arq_explore` recibe **solo** `{input, seed_count}`; `input` es una entrada `arqgen-brief-v8` íntegra y `seed_count` es entero **2–12**. La CLI equivalente es `arqgen-explore ENCARGO.json --rules knowledge/generic-house.json --count N`. Desde `input.seed` se recorren N semillas consecutivas con vuelta modular tras `4294967295`. Cada una reutiliza **la misma enumeración y validación de 48 variantes** de Rust (0 variantes si falla una comprobación previa), incluidas las que el generador individual no seleccionaría entre sus tres propuestas. Las reglas, contorno, trazado, programa y las tres hipótesis de presión son idénticos en todo el lote; **no** se baraja un abanico de reglamentos ni se buscan recorridos distintos del dibujado.
- Rust agrega `generated`, `rejected`, `valid`, `rejection_summary` y por semilla `{seed,input_hash,status,generated,rejected,rejection_summary,reasons}`. Una variante descartada cuenta una vez por su **primer** rechazo. Si ninguna pasa, `status:"infeasible"`, `pareto_front_size:0`, `alternatives:[]`; nunca se inventa un plano o una aprobación. Este estado solo dice que **esta búsqueda** no halló una propuesta: no determina si un solar real es inviable.
- Sobre **todas las variantes validadas en el lote** se calculan en Rust capas de dominancia **estricta, sin epsilon** con cinco números heurísticos ya existentes: `area_fit`, `circulation_score`, `privacy_score`, `service_score` y `east_bedroom_score` (mayor es mejor para cada uno). La clasificación individual mantiene su tolerancia original para preservar archivos v8. `pareto_front_size` cuenta las alternativas no dominadas en el **conjunto muestreado** (incluidas las de geometría parecida). Después se eligen **hasta tres** croquis de las capas, con separación mínima de 0,75 m en la distancia de centros/anchura interna del motor; se favorece un patrón no representado. Se puede mostrar una capa >0 por diversidad y más de una alternativa de la misma semilla. Este frente **no es un óptimo global** ni un indicador de viabilidad legal, higiene, acceso, luz, evacuación o constructibilidad. Solo se dibuja SVG de las seleccionadas, nunca de las rechazadas.
- `exploration_method:"bounded-seed-sweep-v1"` versiona el **método de lote**; no sustituye la versión del motor de una corrida individual. Los croquis son 2D autodeclarados. `bathroom_ventilation_status`, iluminación natural y aplicabilidad normativa siguen `not_evaluated`; los dos puntos del extractor y la reserva de presión siguen siendo **hipótesis inventadas**, sin ficha de fabricante ni caudal entregado. No se convierten PDF o vistas de terceros en reglas cubanas.

## Flujo web, cancelación y exportación

- La sección «Explorar varias semillas» se habilita después de una corrida evaluada (incluso `infeasible`). La exploración y verificación se ejecutan en un **Web Worker desechable**, con el mismo WASM compilado que utiliza la vista individual. Se puede cancelar con `terminate()` sin bloquear el formulario; un token, la revisión del encargo y la secuencia de importación impiden adoptar una respuesta tardía tras cancelar, editar, regenerar, deshacer o abrir otro proyecto. Cambiar el encargo borra el lote en memoria. El SVG se muestra como **imagen** y los textos/trazas se insertan con `textContent`, no como HTML del archivo.
- El lote solo existe en la pestaña y **no** se guarda implícitamente en la cartera, cuaderno de hipótesis, copia rápida ni historial. «Descargar lote JSON» escribe `{format:"arqgen-illustrative-seed-exploration-v1", input, seed_count, exploration}` (≤8 MiB). «Abrir lote y verificar» exige esquema y ruleset demo actual; reproduce con `arq_explore` **todas** las semillas en Rust, compara **todo** el resultado incluido SVG, conteos, hash, trazas y frente, y solo entonces, si hay cambios/proyecto abierto, pide confirmación; regenera también la corrida base, adopta el encargo del archivo, limpia cuaderno/proyecto activo y reinicia historial. Declinar la confirmación no cambia la vista. Un archivo adulterado o incompatible **no sustituye ningún** croquis ni campo. El JSON no está cifrado ni firmado; puede incluir datos autodeclarados. Las corridas v8, comparativas, copia rápida y cartera v1 anteriores siguen separados y no se migran.
- Límites en el puente: entrada WASM ≤256 KiB, respuesta del lote ≤2 MB, archivo JSON ≤8 MiB, 2–12 semillas × 48 intentos como máximo. El build offline precarga el **worker JS** junto al HTML/CSS/JS/WASM; importar y reproducir el lote sin conexión tras la primera visita no confía en cachés de proyectos. Tauri/WebView2 nativo **no fue probado**; worker, protocolo y CSP precisan QA en Windows.

## Verificación reproducible

- `cargo fmt --all -- --check`; `cargo test --offline --locked --workspace`: **78/78** (19 unitarias, 3 del lote, 56 previas). Pruebas de dominancia exacta, conteos por semilla frente a corridas individuales, vuelco `u32`, cero variantes, 96/96 rechazos y límites del sobre.
- `npm ci --prefix web`, `npm run build --prefix web`, `npm test --prefix web`: **71/71** web. Incluye SHA-256 de cuatro respuestas v8 capturadas **antes** de refactorizar el escáner para probar la compatibilidad, paridad CLI↔WASM del lote, caso elegido que no figuraba entre las tres alternativas individuales, replays, límites y mutaciones de SVG, identidad, motivos y metadatos. WASM versionado y build coinciden en SHA-256 `fe95bb201e1bcb92574e09bc196670062fdc75da3b13502f7e2cb56dc6ba0874`.
- E2E del **build**, Chromium headless/Linux: **4/4**. Dos casos nuevos comprueban worker cancelado antes de cargar, resultado tardío ignorado, adulteración rechazada sin mutación, recuperación del encargo/lote válido, SVG visible y replay completo de lote **sin conexión**; los otros dos mantienen la cartera, historial y v8. Este navegador y el toolchain se prepararon temporalmente desde paquetes de terceros fuera de Git; no equivalen a QA Windows/WebView2 ni certificación de los binarios.
